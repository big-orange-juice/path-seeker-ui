# 管理端适配设计

## 信息架构

保留现有管理端入口，不新增“黄包车”页面：

| 现有能力 | 兼容后的含义 | 户外扩展 |
| --- | --- | --- |
| 博物馆 | 目的地 | `sceneType` 区分场馆与户外区域 |
| 楼层 / 展厅 | 场景空间 | 户外使用文化点和地理坐标 |
| 展品讲解 | 文化内容 | 一个文化点关联多个导游讲解版本 |
| 主题路线 | 游览路线 | 停靠点、线路几何、里程、接驳方式 |
| 审核上架 | 发布工作流 | 室内外完全复用 |

## 建议后端字段

- 目的地：`venueType`、`coordinateSystem`、`mapProvider`、`boundaryGeoJson`、地图中心点。
- 文化点：`destinationId`、经纬度、类型、地址、建议停留时间、发布状态。
- 讲解版本：`placeId`、`guideId`、风格、讲解词、音频、时长、审核状态。
- 路线：`sceneType`、`geometryGeoJson`、里程、预计时长。
- 路线节点：`placeId`、顺序、抵达说明、交通方式、停留时长。

## 工作流

运营先创建目的地，再维护场景内容；路线只引用同一目的地下的文化点或展厅节点。路线保存后继续走现有“草稿 → 提交审核 → 审核通过并上架”，从而避免为黄包车项目复制权限、审核和发布逻辑。
