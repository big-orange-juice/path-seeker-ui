# C 端用户车夫授权

## 管理操作

1. 车夫先在 C 端登录。支付宝小程序用户可在「我的」查看账号编号，便于管理员核实身份。
2. 管理员进入 B 端「C端用户管理」，按手机号、昵称或账号编号查询用户。
3. 点击「车夫权限」，勾选「是否车夫」，确认手机号并保存。尚未绑定手机号的小程序账号可在此由管理员确认绑定；已有手机号不能在此改为其他号码。
4. 用户进入「实时讲解」，选择讲话语言后直接创建房间，无需选择车辆。
5. 取消「是否车夫」并保存可撤销授权；进行中的房间会在下一次权限检查时关闭，后台定期检查间隔为 15 秒。

「用户管理」继续管理 B 端账号。「黄包车管理」菜单隐藏，原页面地址跳转到 C 端用户管理。历史车辆资料和其他扫码业务数据保留。

## 权限规则

- 只有正常、未删除的非游客账号可以获得车夫权限。
- 管理员确认的手机号必须与当前登录账号的手机号一致；仅有相同手机号的其他账号不会继承授权。
- 一个房主账号同一时间只保留一个有效房间。创建接口只接收讲话语言。
- 翻译和语音使用独立的讲解翻译会话，不依赖车辆或场馆。

## 上线顺序

1. 对已有数据库先执行后端 `doc/98-app-user-driver-permission.sql`。新环境先执行 `97-translation-room-ddl.sql`，再执行 98 脚本。
2. 首次执行 98 脚本时，将当前启用车辆中已绑定正常账号且手机号匹配的授权迁移到用户。脚本重复执行不会恢复已撤销的权限。
3. 部署后端、B 端、H5 和支付宝小程序。新版客户端使用 `GET /api/TranslationRooms/host-permission`，返回 `{ canHost: boolean }`。
4. B 端通过 `POST /api/AppUser/PageList` 查询用户，通过 `POST /api/AppUser/ChangeDriver` 保存 `{ userId: string, isDriver: boolean, phone?: string }`。

本次仅提供迁移脚本，不直接修改运行中的数据库。
