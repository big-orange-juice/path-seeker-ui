# 博物馆导览解密项目开发方案（对齐简化版产品方案）

## 1. 方案目标

这份开发方案只回答三个问题：

- 当前仓库应该承接哪些前端工作。
- C 端体验流程应该如何拆成页面、状态和接口。
- 难度模型收敛后，B 端、C 端、服务端要如何统一协议。

### 1.1 当前范围

| 项目 | 说明 |
| --- | --- |
| 当前仓库 | 前端 monorepo，仅覆盖 B 端后台与 C 端小程序 |
| 当前目标 | 先把可落地的内容配置流和 C 端主流程跑通 |
| 不在本仓库 | `.NET` 服务端实现、数据库迁移、正式部署工程 |
| 当前优先级 | 先对齐产品结构和协议，再推进真实页面与接口接入 |

### 1.2 与产品方案的对齐原则

| 原则 | 开发含义 |
| --- | --- |
| C 端是实地探秘流程，不是答题工具 | 页面组织必须围绕章节推进、线索回收和终局结算 |
| 只保留“年龄档 + 难度档” | 不再把提示次数、步骤数、干扰度拆成多个运营字段 |
| 题型负责交互，不负责定义难度 | 题型 schema 只描述渲染与作答方式 |
| 路线要轻量可复用 | 单条路线、单题、单章节都必须可配置、可回放、可复盘 |

## 4. C 端开发方案

当前产品核心是 C 端体验，因此开发方案要优先围绕主流程拆解，而不是先从零散题型页开始做。

### 4.1 C 端主流程拆解

| 阶段 | 页面 | 前端职责 | 服务端依赖 |
| --- | --- | --- | --- |
| 1 | 首页 / 任务大厅 | 拉取路线列表、展示推荐、按年龄档和时长筛选 | 路线列表接口 |
| 2 | 任务详情 | 展示路线信息、起点、奖励、适龄说明 | 路线详情接口 |
| 3 | 开始任务 | 创建或恢复会话 | 会话创建 / 恢复接口 |
| 4 | 开场剧情 | 展示开场文案、角色引导、首站目标 | 路线章节摘要接口 |
| 5 | 章节地图 | 展示当前章节、已获线索、待完成目标 | 会话状态接口 |
| 6 | 展品观察页 | 展示展品信息、观察点、线索背景 | 展品 / 线索接口 |
| 7 | 谜题页 | 渲染题型、提交答案、拉取提示、记录结果 | 谜题详情 / 作答 / 提示接口 |
| 8 | 章节过场 | 展示线索变化、奖励变化、下章节入口 | 章节结算接口 |
| 9 | 终局结算 | 展示真相、成绩、奖励、分享卡 | 终局结算接口 |

### 4.2 页面职责定义

#### 首页 / 任务大厅

| 项目 | 说明 |
| --- | --- |
| 页面目标 | 让用户快速找到适合自己的路线 |
| 核心模块 | 推荐路线、活动入口、年龄档筛选、时长筛选 |
| 状态要求 | 支持初次进入与最近游玩恢复入口 |
| 技术重点 | 列表缓存、骨架屏、筛选状态持久化 |

#### 任务详情页

| 项目 | 说明 |
| --- | --- |
| 页面目标 | 让用户决定是否开始任务 |
| 核心模块 | 剧情简介、适龄、时长、章节数、奖励、起点 |
| 状态要求 | 支持收藏、分享、恢复未完成任务 |
| 技术重点 | 数据结构稳定，避免和大厅列表字段割裂 |

#### 开场剧情页

| 项目 | 说明 |
| --- | --- |
| 页面目标 | 从浏览模式切到任务模式 |
| 核心模块 | 角色引导、任务目标、第一站提示 |
| 状态要求 | 可跳过动画，但不能跳过任务上下文 |
| 技术重点 | 音频、文本、动效解耦，兼顾弱网 |

#### 章节地图页

| 项目 | 说明 |
| --- | --- |
| 页面目标 | 成为全流程导航中枢 |
| 核心模块 | 当前章节、目标展厅、已获线索、路线进度 |
| 状态要求 | 必须可从中断状态直接恢复 |
| 技术重点 | 本地缓存与服务端状态合并、线索板更新 |

#### 展品观察 / 线索页

| 项目 | 说明 |
| --- | --- |
| 页面目标 | 先观察展品，再进入题目 |
| 核心模块 | 展品图、位置提示、观察点、故事片段、进入题目按钮 |
| 状态要求 | 已看过与未看过状态可区分 |
| 技术重点 | 图片细节查看、位置提示、短文案节奏 |

#### 谜题页

| 项目 | 说明 |
| --- | --- |
| 页面目标 | 完成单次高反馈互动 |
| 核心模块 | 题面、选项或交互区、提示入口、提交结果、反馈动画 |
| 状态要求 | 支持重试、提示、跳过、恢复未完成作答 |
| 技术重点 | 动态题型渲染、作答结构统一、提示状态机 |

#### 章节过场页

| 项目 | 说明 |
| --- | --- |
| 页面目标 | 把答题结果转成剧情推进 |
| 核心模块 | 新线索卡、剧情推进文案、奖励碎片、下一站提示 |
| 状态要求 | 可回看，但不应重复结算 |
| 技术重点 | 结算 idempotency、奖励状态同步 |

#### 终局结算页

| 项目 | 说明 |
| --- | --- |
| 页面目标 | 形成完整闭环和分享动力 |
| 核心模块 | 真相揭示、知识总结、成绩卡、徽章 / 称号、分享图 |
| 状态要求 | 可重复进入，可单独查看奖励 |
| 技术重点 | 分享卡数据聚合、成绩计算展示 |

### 4.3 C 端状态模型

建议至少拆出以下 store：

| Store | 作用 |
| --- | --- |
| `useSessionStore` | 当前会话、章节进度、恢复状态 |
| `useTaskStore` | 路线列表、详情、推荐信息 |
| `useClueStore` | 已解锁线索、线索板、章节线索变化 |
| `usePuzzleStore` | 当前题目、作答过程、提示层级、提交结果 |
| `useRewardStore` | 徽章、碎片、结算奖励 |
| `useAppStore` | 网络状态、音频状态、全局 loading、首次引导 |

### 4.4 C 端关键交互规则

| 场景 | 规则 |
| --- | --- |
| 提示 | 固定三级：观察提示、关系提示、直接提示 |
| 卡关 | 允许重试和跳过，但要记录提示次数与跳过状态 |
| 中断恢复 | 进入小程序优先恢复最近会话，而不是回首页重选 |
| 弱网 | 当前章节、当前题面、已获线索必须可基础缓存 |
| 亲子同行 | 以陪伴提示和协作任务处理，不扩出单独题库体系 |

### 4.5 C 端埋点建议

| 埋点 | 用途 |
| --- | --- |
| 进入任务详情 | 看路线吸引力 |
| 点击开始任务 | 看转化率 |
| 到达章节地图 | 看任务进入成功率 |
| 打开展品观察页 | 看线索页使用情况 |
| 请求提示 | 看难度是否过高 |
| 跳过题目 | 看是否存在明显卡关 |
| 章节完成 | 看中段流失 |
| 到达终局 | 看整条路线完成度 |
| 生成分享 | 看传播意愿 |

## 5. 难度模型与协议设计

### 5.1 难度模型落地原则

| 项目 | 规则 |
| --- | --- |
| 年龄档 | 只负责文案语气、理解方式、知识解释深度 |
| 难度档 | 只负责线索显性、步骤数、干扰度、提示强度 |
| 题型模板 | 只负责交互渲染与答案结构 |
| 早期版本 | 只支持 `6-10`、`10-15` 两档年龄，`L1-L3` 三档难度 |

### 5.2 推荐枚举

| 枚举 | 建议值 |
| --- | --- |
| `ageBand` | `age_6_10`、`age_10_15`、`age_15_plus` |
| `difficultyLevel` | `l1_observe`、`l2_associate`、`l3_reason` |
| `templateType` | `observe_choice`、`clue_find`、`sort`、`match`、`code_break` |
| `hintLevel` | `observe`、`relation`、`direct` |

#### 首期固定题型与渲染器

| templateType | 中文名 | 渲染器组件 | 典型输入 | 答案结构 |
| --- | --- | --- | --- | --- |
| `observe_choice` | 观察选择 | `ObserveChoiceRenderer` | 题干 + 选项列表 | 单个正确选项 |
| `clue_find` | 细节找线索 | `ClueFindRenderer` | 图片 / 观察区域 + 目标描述 | 热点或区域命中 |
| `sort` | 排序 | `SortRenderer` | 待排序项列表 | 正确顺序数组 |
| `match` | 配对 | `MatchRenderer` | 左右两列关系项 | 配对关系数组 |
| `code_break` | 密码解锁 | `CodeBreakRenderer` | 线索描述 + 密码输入位 | 正确密码或片段组合 |

渲染器层先只实现这 5 个组件，`templateType` 到渲染器组件采用一对一映射，不在首期引入通用大而全渲染器。

### 5.3 题目数据模型建议

```ts
interface PuzzleDefinition {
  id: string
  templateType: TemplateType
  ageBand: AgeBand
  difficultyLevel: DifficultyLevel
  title: string
  prompt: string
  introText?: string
  questionPayload: Record<string, unknown>
  answerPayload: Record<string, unknown>
  hintPayload: {
    observe?: string
    relation?: string
    direct?: string
  }
  rewardPayload?: {
    clueId?: string
    fragmentId?: string
  }
  mediaPayload?: {
    coverImage?: string
    detailImages?: string[]
    audioUrl?: string
  }
}
```

### 5.4 会话数据模型建议

```ts
interface GameSessionSnapshot {
  sessionId: string
  routeId: string
  ageBand: AgeBand
  currentChapterId: string
  completedPuzzleIds: string[]
  unlockedClueIds: string[]
  rewardIds: string[]
  lastPuzzleState?: {
    puzzleId: string
    usedHints: HintLevel[]
    answerDraft?: unknown
  }
}
```

### 5.5 章节结构建议

| 字段 | 说明 |
| --- | --- |
| `chapterId` | 章节唯一标识 |
| `title` | 章节标题 |
| `targetLocation` | 展厅 / 展柜目标位置 |
| `artifactIds` | 本章节关联展品 |
| `puzzleIds` | 本章节关联题目 |
| `completionRule` | 完成条件 |
| `nextChapterId` | 下一章节 |
| `resultNarrative` | 本章完成后的过场文案 |

## 6. B 端开发方案

### 6.1 B 端页面优先级

| 页面 | 目标 |
| --- | --- |
| 概览页 | 统一展示产品结构与当前规则 |
| 馆藏管理 | 把展品整理成可出题资产 |
| 谜题工坊 | 围绕“年龄档 + 难度档 + 题型模板”生成题目 |
| 路线编排 | 章节顺序、起点、终局、奖励配置 |
| 运营页 | 查看完成率、提示率、卡关题 |

### 6.2 B 端字段收敛原则

| 旧思路 | 新规则 |
| --- | --- |
| 每题手动配置大量难度维度 | 改为只选年龄档、难度档、题型模板 |
| 单题维护多套低龄版本 | MVP 阶段最多维护 2 个版本 |
| 提示次数单独配置 | 改为难度档默认策略 |
| 题型复杂度也算难度 | 题型与难度解耦 |

### 6.3 B 端核心表单结构

| 模块 | 关键字段 |
| --- | --- |
| 馆藏 | 基础信息、展厅位置、媒体资源、标签、观察点、故事片段 |
| 谜题 | 题型模板、年龄档、难度档、题面、答案、提示、奖励 |
| 路线 | 开场文案、章节顺序、起点位置、终局题、结局文案、奖励 |
| 发布 | 状态、版本号、生效时间、适用活动 |

## 7. 服务端与接口边界建议

当前仓库不实现服务端，但前端需要按以下边界准备。

### 7.1 服务划分

| 服务 | 责任 |
| --- | --- |
| `ApiService` | 馆藏、谜题、路线、会话、奖励、埋点、后台管理 |
| `AgentService` | 出题草稿、提示生成、剧情改写、风险审核 |

### 7.2 API 分层

| API | 使用方 | 作用 |
| --- | --- | --- |
| Admin API | B 端后台 | 配置、审核、发布、复盘 |
| Mini API | C 端小程序 | 路线获取、会话恢复、答题、结算 |
| AI API | B 端后台 / Agent 回调 | 草稿生成、审核结果回写 |

### 7.3 C 端关键接口建议

| 接口 | 用途 |
| --- | --- |
| `GET /mini/routes` | 获取路线列表 |
| `GET /mini/routes/{id}` | 获取路线详情 |
| `POST /mini/sessions` | 创建会话 |
| `GET /mini/sessions/{id}` | 恢复会话 |
| `GET /mini/chapters/{id}` | 获取章节信息 |
| `GET /mini/artifacts/{id}/clue` | 获取展品观察页数据 |
| `GET /mini/puzzles/{id}` | 获取谜题详情 |
| `POST /mini/puzzles/{id}/submit` | 提交答案 |
| `POST /mini/puzzles/{id}/hint` | 获取下一层提示 |
| `POST /mini/chapters/{id}/complete` | 章节结算 |
| `POST /mini/sessions/{id}/finale` | 终局结算 |

## 8. AI 辅助能力建议

### 8.1 适合先做的 AI 能力

| 能力 | 作用 |
| --- | --- |
| 谜题草稿生成 | 根据展品和年龄档输出初版题面 |
| 提示文案生成 | 自动补全三级提示 |
| 剧情包装 | 为路线输出开场与章节过场文案 |
| 标签建议 | 从馆藏内容里抽线索点和观察点 |

### 8.2 暂不建议优先投入的能力

| 能力 | 原因 |
| --- | --- |
| 完全自动发布 | 风险过高，缺少人工把关 |
| 复杂多 Agent 长流程 | 当前项目还没到工程收益显著阶段 |
| 高自由度开放问答 | 与当前线下实地流程不匹配 |

| 阶段 4 | 接入动态题型与会话流 | 题型渲染器、作答提交、章节推进 |
| 阶段 5 | 打通结算、复盘和 AI 草稿链路 | 终局结算、后台复盘、AI 草稿入口 |
| 阶段 6 | 联调与体验打磨 | 弱网、音频、节奏、分享体验 |

## 12. 结论

| 项目 | 结论 |
| --- | --- |
| 当前开发重点 | 先把 C 端主流程做完整，再扩复杂题型 |
| 协议重点 | 用统一 schema 承接年龄档、难度档、题型模板 |
| 后台重点 | 降低运营配置复杂度，避免字段爆炸 |
| 小程序重点 | 让用户始终知道“去哪、看什么、为什么、接下来做什么” |
| 工程策略 | 先用少量路线、少量题型、少量状态把主链路跑通 |
