# 车夫 APP 讲解与游客跟随

## 角色与房间

Android 0.3.0 使用现有 `TranslationRooms` 作为唯一房间：创建、恢复、二维码邀请、讲话语言、后台收音和定位都绑定同一字符串 roomId。支付宝小程序默认游客模式，保留加入、切语言、收听及提问，拒绝房主从小程序接管 APP 连接。

## APP 收音

用户从可见页面同意用途说明并授予录音权限后启动 `microphone` 前台服务。采集 16kHz、单声道、16bit little-endian PCM，每帧约 100ms，经 `wss://www.omahaaigc.com/path-seeker/api/TranslationRooms/{roomId}/events` 上传。请求带 Bearer 令牌和 `translation` 子协议。

收到 `room.snapshot` 后发送 `input.start`，收到 `room.started` 才开始采音。暂停先停止 AudioRecord，再发 `input.pause`，等到 `input.paused` 才允许继续。服务端尾段识别期间界面显示正在完成识别。控制帧及业务心跳约 15 秒；断线有限退避重连，积压超过约 3 秒音频时停止并提示，不补传断线期间讲话。

提问通过现有 `question.updated` 定向接收。音频只放内存，按服务端有效期清理，播放前暂停收音并等待确认，播放结束后手动恢复。定位与麦克风服务独立，暂停收音不停止定位，结束房间停止两者。系统终止后不自动恢复麦克风。

## 游客读取车夫坐标

新增 `GET /api/TranslationRooms/{roomId}/location`。仅 `user` / `guest` 账号可调用，校验有效用户、房间成员、车夫授权及未结束房间；返回 `Cache-Control: no-store`。不使用管理员位置列表，也不返回手机号、其他房间或历史轨迹。

```json
{
  "roomId": "9223372036854775805",
  "serverTime": "2026-11-03T02:00:00Z",
  "status": "online",
  "longitude": 116.4,
  "latitude": 39.9,
  "accuracy": 10,
  "sampledAt": "2026-11-03T01:59:58Z",
  "coordinateSystem": "GCJ-02"
}
```

接口使用已有 `ApiResponse` 外层。停止、等待、过期或离线状态不返回可用经纬度。游客接口以 15 秒判定样本过期，B 端展示仍沿用原有 30 秒状态阈值。

小程序只从当前已连接游客房间拉取坐标，每次请求完成后等待 1 秒，无本机定位回退。地图使用车夫 GCJ-02 坐标；范围计算保持现有 WGS84 约定。重复及倒序采样不驱动新判定，也不延长样本寿命。客户端根据服务端时钟和请求耗时检查样本年龄，超过 15 秒或请求失败立即清除判定、提示卡和车夫标记。关闭跟随、换房、离房或切账号取消旧请求并拒绝迟到响应。

游客未加入房间或关闭跟随时不自动触发。实时讲解占用声音时可检测和排队，景点播放继续等待声音释放。支付宝挂起 JS、网络或音频后无法保证新站点实时播放；车夫 APP 后台正常不等于游客小程序能持续运行。

## 部署与验收

2026-11-03 增加游客房间恢复与音频调度修复：

- 同账号、同 API 环境保留房间号、字符串 roomId、语言和静音/跟随偏好，前台恢复及冷启动先重新入房再订阅；订阅确认后恢复位置跟随。
- 前台连接异常按 1、2、4、8、16、30 秒退避重试；握手 15 秒超时或持续缺少业务 pong 也会重连。后台不持续发重连请求；断线期间语音不会补播。
- 主动结束行程成功或离房、退出账号、确认房间失效时清除恢复信息，并取消未完成请求。结束行程失败保留房间；旧请求迟到不得恢复已退出的房间。
- 服务端输入轮次识别和提交全部完成后广播 `room.input.drained`，沿用外层字符串 `epochId`；快照增加 `inputDraining`。该信号不代表翻译及播放结束，客户端还要等待各段译文完成和译音队列排空。
- 未开始讲解或暂停后所有尾段处理及播放完成时，景点队列可以继续；车夫续讲优先打断景点并保存时间，结束后从该进度恢复。附加音视频遵循相同优先级。

本次必须先部署带排空信号的后端，再更新支付宝小程序；旧后端缺少该信号，不能完整实现暂停后的自动接续。本次无需数据库迁移，也无需因本次修复重新安装 Android APP。

1. 部署新增房间坐标接口，再预览或发布本次小程序 `dist`；接口未部署时提示服务不可用，不回退本机定位。
2. 安装同签名 0.3.0 发布 APK，可覆盖升级 0.2.0；使用已授权的车夫账号登录。
3. APP 创建房间后用另一个账号在小程序加入。保持游客手机不动，仅移动车夫手机，验证地图标记、近站稳定判断、提示卡和排队。
4. 验证停止位置共享、断网、旧样本、离房、换房及关闭跟随均不继续触发；同一坐标重复查询不能伪装成持续新采样。
5. 验证 APP 暂停、继续、断网重连、游客提问、来电及锁屏；真机测试高德鉴权、厂商电池限制和真实 ASR/翻译链路。

本轮无需新数据库迁移，继续使用已有定位历史表和至少 24 小时留存。构建与模拟测试不代替真机验收；本机尚无连接的 Android 设备。
