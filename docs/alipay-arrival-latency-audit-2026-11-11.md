## 已确认的判定差异

两端都使用同一房间的司机 APP 定位、同一目录接口的点位与范围，并把 GCJ-02 转为 WGS84。当前小程序 `routeCorrection=false`，未启用额外道路吸附。核心默认值相同：接近 50 米、解除 80 米、允许定位精度最多 65 米、位置最多 15 秒、停留至少 1.5 秒。点位单独配置的范围和阈值优先，不能把所有点都理解成“中心 50 米”。

具体实现仍存在以下差异，本轮已修复服务端：

| 情况 | 修复前服务端 | 小程序与本轮服务端 |
| --- | --- | --- |
| 两个有效采样间隔 7～15 秒 | 超过 6 秒就清除已进入范围的停留记录 | 两个样本均满足时效性时，保留停留；超过 15 秒重新累计 |
| 两次采样间隔 7～15 秒、移动距离不超过 120 米 | 不检查采样间经过的范围 | 可进行经过范围的线段补偿，保留朝向条件，拒绝超过 120 米的大跨度 |
| 短时收到差精度定位 | 上游直接返回空值，立即清除停留 | 保留质量信息交给判定器；6 秒内最多容忍两个不同的差精度样本，差样本自身绝不触发，须后续有效样本确认 |
| 节点 `triggerRadiusMeters=0` 或负值 | 当作实际接近距离使用 | 按小程序规则回退到默认值；景点范围明确设置 `proximityDistanceMeters=0` 仍保留为 0 |

新增的最初 9 个后端回归中，修复前 7 个失败、2 个通过；修复后 9 个全部通过。随后补充了连续弱定位、过期、未来时间与诊断计数保护，并保留既有去重、终点前序和圆形/多边形内环用例。小程序增加对应的线段时效、默认阈值契约验证。

## 为什么触发了仍可能晚出声

完整链路包含：司机采样 → 上传 → 服务端到站确认 → 排队 → 下载/解码 → PCM/MP3 输出 → HTTP/支付宝缓存 → 手机出声。

司机 APP 定位间隔配置为 1.5 秒；上传任务在上次请求完成后再等 1.5 秒，并非网络慢时也严格每 1.5 秒上传。服务端约每秒取一次最新样本；到站仍需要两个不同时间的有效定位，样本不能靠轮询同一份坐标重复累计。定位迟到或精度较差会影响前几站，后续恢复时可以出现“前半段不触发、后半段触发”。这是待轨迹验证的可能性。

此外，当前调度规则保留两种等待：

1. 车夫房间输入、翻译或房间音频有优先权时，路线等待；即使此刻没有听到房间声音，也可能仍处于等待输入结束或翻译完成的状态。
2. 已经播放的路线节点按顺序讲完，再播下一个已到站节点。新节点只打断空闲节目，不直接打断上一节点讲解。这可能表现为到站后声音晚到，并不等于范围判断失败。

即使服务端已开始生成新音频，手机中已缓冲的上一段仍可能继续播放。之前提供的诊断中，服务端媒体时钟比手机领先约 22.8 秒；那是此前记录，不能当作本次的实测延迟。

## 本轮新增诊断

到站诊断首次加入版本为 `tour-audio-arrival-20261111`，最新版本为 `tour-audio-player-state-20261111`。记录不包含媒体票据和登录凭证，新增字段来自服务端，锁屏期间照常累计：

| 字段 | 用途 |
| --- | --- |
| `server.arrival.status` | `valid`、`weak-accuracy`、`stale`、`future`、`unavailable` 或重复/乱序样本 |
| `server.arrival.rejectedSamples` | 按原因累计拒绝的不同样本；无定位按连续不可用状态计数，不是秒数 |
| `server.arrival.maximumSampleGapSeconds` | 两个有效样本之间观察到的最大间隔 |
| `server.arrival.candidates` | 最近六个候选的字符串节点 ID、距离、有效进入/解除阈值、停留时间，以及范围外、停留中、前序不满足、已排除等状态 |
| `server.schedulerStatus` | 等待到站、正在解码、路线播放、房间优先、暂停、挂起、自动播放关闭或内容锁定 |
| `server.stageTimings` | 每个节点首次相关阶段的采样、到站、选中和首次 PCM 音频生成时间 |
| `server.completedStageIds` | 检查是否被已有完成记录排除 |
| `lagSeconds` / `audible` | 手机媒体时间与服务端时间差、手机时间线对应的内容 |

`audioStartedAt` 表示服务端首次为该节点生成 PCM 帧，不代表已送达手机，也不代表游客实际听到。字段仅记录阶段，不自动推算网络延迟。

服务端增加 `Tour arrival state` 日志：首次或异常状态变化时输出，常态约 30 秒一次；包括样本质量和附近点位判定，不记录原始经纬度。`Tour arrival` 表示入队，`Tour audio first frame` 表示首次生成该节点音频。由这三类日志判断“前半程没有入队”和“已入队但等待/缓冲”非常直接。
