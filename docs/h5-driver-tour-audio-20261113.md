# H5 跟随车夫与服务端持续讲解

H5 的游客跟车模式复用现有 `TourAudioSessions` 协议。游客加入未结束的讲解房间、开启“跟随车夫”并开始路线游览后，由服务器读取车夫位置、判断到站并编排景点音频、沿途趣事和房间实时讲解，浏览器只播放一条持续 MP3 连接。

## 页面与播放职责

- `useDriverTour` 负责房间、路线和游览生命周期的接线，以及车夫位置展示。
- `tourAudioSession` 管理会话创建、串行控制、播放意图、媒体连接、状态刷新和进度确认。
- `useTourJourney` 在服务端管理期间停止游客 GPS、本地到站判断、本地音频队列和自动进度写入。服务端返回的游览记录是跟车进度的依据。
- 跟车时浏览地图或内容抽屉只查看节点，不改变正在播放的音频；手动选播、拖动进度和修改队列需关闭跟随。
- 房间字幕连接继续保留，但房间独立 PCM 播放器停止，避免实时讲解与持续 MP3 重复出声。房间静音只改变服务端的实时讲解偏好。

## 重连语义

显式点击“重新连接”时执行 `realign → resume → reconnect`，清除未完成的旧节点队列和旧媒体缓冲，重新按车夫当前有效位置及既有到站规则调度。车夫不在可触发景点范围时等待下一次有效到站；完成记录和前置到访条件继续有效。播放器节点名称与章节进度根据当前媒体连接的时间线显示，避免把服务器已生成但游客尚未听到的后续节点提前显示出来。

提问开始、主动暂停、退出房间、切换账号或路线会使旧操作失效。连续点击重连共用同一次操作。普通暂停恢复和问答恢复保留原服务端续播语义，不自动调用 `realign`。

## 房间恢复与结束

即时解散通过房间关闭事件停止持续讲解，清除播放错误，并显示“车夫已解散房间”。退出跟车时不会自动启动本地讲解，之后仍可手动播放路线。

创建会话遇到精确的 `403 / 10003 / 请先加入房间` 时，先重加原房间确认成员资格；恢复成功只重试一次创建。只有房间重加结果明确表示结束，才按正常关闭处理。其他权限或网络错误保留真实反馈。会话本身结束不直接等同于车夫解散房间，需要核对原房间状态。

## 浏览器与发布

此变更没有增加 H5 息屏收听开关。H5 进入后台时暂停持续讲解，返回前台刷新状态并恢复必要的房间连接，音频等待用户继续播放或点击重新连接。支付宝原生音频中断事件不适用于浏览器，此变更不提供电话和微信通话结束后的跨平台恢复保证。

浏览器可能阻止自动播放。显式播放或重连时同步准备可播放的音频元素，在异步接口返回后复用；播放被拒绝时保留清晰的手动恢复入口。需要在 Android Chrome、iOS Safari 和微信内置浏览器分别验证真实播放及后台行为。

需要构建并部署新版 H5 静态资源；后端须已部署持续讲解接口并正确代理持续 MP3（禁用响应缓冲、允许长连接、不缓存）。复用小程序现有服务端能力，无需为本次改动新增后端协议。若 H5 与 API 跨域，应保留已有的 API CORS 与 HTTPS 配置。

## 验证

自动化覆盖持续音频会话、字符串长 ID、创建去重、旧队列重对齐、媒体时间线、迟到响应失效、后台暂停、成员恢复、房间关闭、独立房间音频抑制，以及跟车与手动模式切换。执行：

```sh
pnpm --filter @path-seeker/h5-client type-check
pnpm --filter @path-seeker/h5-client test
pnpm --filter @path-seeker/h5-client build
```

实机重点：A 节点未播完时车夫移至 B 后手动重连；车夫不在景点范围时重连；息屏返回后手动继续与重连的区别；车夫即时解散；重连过程中提问、暂停、退出房间及切换账号；已完成节点和前置节点规则；弱网和浏览器自动播放拦截。
