# 支付宝持续讲解：启动保护与诊断

诊断版本：`tour-audio-startup-guards-20261113`。

## 行为

- 连接前校验登录、运行环境、游客房间、路线、进行中的游览以及游览与路线的一致性。缺少条件时给出可操作的提示。
- 创建会话期间显示“正在连接讲解，请稍候”；创建失败显示“讲解未连接，请重试”并保留错误信息。浏览节点不会清除服务端讲解错误。
- 同一上下文的创建请求继续复用；创建中重复点击重试不提交额外请求。跟随模式下手动重连的创建和恢复操作作为一个进行中的操作处理。
- 创建失败阻止同一账号版本、房间、游览、路线、导游、语言上下文自动反复创建；更换上下文后允许再次连接。
- 创建 POST 超时可能已经在服务端生效，因此不自动重放。用户检查网络后点击重试；已知旧会话的迟到结果仍由原有清理机制处理。彻底消除超时后服务端重复创建的风险需要后端幂等支持。
- 保留已有的播放停滞检测及跟随模式下最多三次自动恢复。用户暂停、问答占用、后台状态继续遵守原有保护。
- 不支持后台持续音频的环境保留原有普通播放回退；复制诊断会显示持续讲解不受支持的原因。

## 如何排查无声

1. 页面显示连接失败时，检查错误提示，补齐路线/游览等条件或恢复网络，再点击重试。
2. 仍无声时复制诊断，先看 `startup.readiness`、`startup.busy/loading/asking` 和 `startup.automaticRetryBlocked`。
3. 查看 `phase`、`error`、最近十二条 `lifecycle`。创建开始、成功、失败、取消及停止会话都会记录；创建失败记录 HTTP 状态码和数字业务错误码。
4. `active=false` 仅表示采样时没有活动会话。停止会话后仍保留最近事件，不能凭空会话 ID 断言从未发起过创建。
5. `phase=playing` 要求属于当前会话的原生播放器处于播放状态且媒体时间大于零；这仍不能证明设备扬声器有声。等待节点期间的静音、系统音量及蓝牙输出需结合实际情况判断。

错误字段中的媒体 URL、Bearer 凭证和常见 token 参数会脱敏；退出或切换账号版本时清除历史。历史仅在内存中保留，进程重启后不保留。

## 验证与发布

- 构建：`pnpm --filter @path-seeker/mp-alipay build`
- 专项：在 `apps/mp-alipay` 下运行 `node --test tests/server-tour-audio.test.cjs`
- 全量：`pnpm --filter @path-seeker/mp-alipay test`
- 真机验收：加入房间但未开始游览、断网创建、连续点击重连、切换房间、失败后浏览节点、前后台切换及锁屏恢复。

需要发布新的支付宝小程序版本才会对线上用户生效。此改动不修改后台静音素材设置或每用户语言路由。
