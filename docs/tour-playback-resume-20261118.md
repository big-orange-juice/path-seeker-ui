# 讲解断点恢复与终点退出

适用端：支付宝小程序 `apps/mp-alipay`，配套后端 `TourAudioSessionService`。前后端需要一起发布。

2026-11-19 更新：跟随车夫模式恢复断点后，增加“到下一节点触发范围前是否可播完”的预算判断；可播完才续播，否则静音等待下一有效到站。原文中无条件优先恢复旧节点的行为以 [重连续播预算说明](tour-resume-distance-budget-20261119.md) 为准。

## 行为

- 同一游客、房间、行程、路线、讲解员、语言及额外音频配置下，重新进入并开启跟随时，优先恢复上次实际听到的节点、片段和秒数。
- 客户端保存本地断点，并在前台约每两秒上报实际播放器时间；暂停、录音打断、切后台时补存。服务端用音频时间轴换算片段位置，并在现有 Redis 中保存 24 小时，不需要数据库迁移。
- 本地与服务端断点均有效时采用较新的记录。音频清单、地址或排序变化时，内容指纹不匹配，旧断点失效。
- 语音提问通过 `hold` 暂停讲解，携带当前媒体流及实际播放时间；交互结束后释放，重建媒体连接时恢复该片段的偏移。续播仍可正常确认节点完成。
- 路线最后一个节点的全部音频播放完且客户端确认后，停止自动播放和跟随、退出当前游客房间、清除房间自动恢复信息，返回路线总览。不会解散车夫房间，也不会让其他游客退出。
- 终点发送完成不代表用户听完：等待播放确认期间不会转回旧排队节点或播放沿途趣事。
- 普通本地播放器在最后一个节点自然播放完成后执行相同的退出行为。

## 验收

1. 第一站多个片段中听到第二段中间，关闭小程序，车夫移动到下一站，再进入同一行程：从第一站第二段断点继续。
2. 录音、发送语音及问答结束后：从录音开始时的断点继续；期间定位变化不覆盖断点。
3. 断点保存后重启服务端，再进入：从 Redis 断点恢复。
4. 最后一站尚有手机缓存未播完：仍留在房间；实际播完确认后：关闭跟随、退出游客房间，不再重新开始。
5. 终点退出后切后台再返回、页面刷新：不会自动重新加入原房间。
6. 切换账号、行程、房间、语言、讲解员或改变音频内容：不会串用不匹配的断点。

强制杀进程可能无法发送最后一次进度；恢复到最近保存点，允许少量回退重听。锁屏时平台暂停 JavaScript，服务端只能保留最后收到的实际播放位置，不能将发送进度当作用户听完进度。多机型、来电和真机强制退出仍需发布前实测。
