## 已修复的问题

| 问题与触发条件 | 原来的结果 | 修复 |
| --- | --- | --- |
| API 重启或媒体会话失效，查询或控制返回会话不存在 | 客户端仍持有旧会话，重试继续请求旧 ID | 释放失效会话和旧播放器，保留可见错误；点击重试创建新会话 |
| 恢复播放请求失败，随后状态轮询成功 | 请求错误被正常状态覆盖，页面难以解释无声 | 单独保留控制错误，相关重试成功或后续有效用户控制后再清除 |
| 重连时新媒体源立即解码失败 | 把新连接错误当作旧连接关闭事件忽略 | 使用播放器代次区分重连前后错误，新源错误正常显示 |
| 暂停或挂起后点击“回到现在” | 后端或原生播放器仍被暂停，位置更新但无声 | 同时清除后端暂停与挂起，再恢复原生媒体连接 |
| “回到现在”请求尚未完成，用户立即提问 | 迟到响应接着调用恢复，覆盖新问答的挂起意图 | 将 realign 纳入意图版本检查，失效响应不再触发后续恢复 |
| 锁屏媒体按钮暂停后再次播放 | 内部重复暂停清掉原生暂停标记，播放回调无法正确恢复 | 保留原生暂停来源，允许对应的原生恢复路径 |
| 豆包直接翻译的原文和译文使用独立序号 | 原文序号残留在待翻译集合，路线讲解被误判仍需等待 | 根据源语言、目标语言及 provider 区分序号模式；按讲话轮次与序号跟踪真实翻译片段，并处理 committed、final、error |
| 正式节点已播送、尚未确认收听时预览同节点 | 预览删除正式播放的待确认记录，完成进度不能正常写入 | 预览保留正式播送凭据，确认仍校验媒体流 ID 和播放时间 |
| 手动播放补充音频或视频时操作暂停、播放、进度 | 控件作用到路线流，轮询还会覆盖补充内容进度 | 控件跟随当前播放器所有者；保留补充内容进度，路线继续挂起直到补充内容结束 |

回归测试对延迟响应、错误返回、原生媒体事件和翻译事件顺序进行可控模拟。关键缺陷在修复前已复现失败，修复后通过。另覆盖“正式节点被预览打断，再选其他节点”时原正式队列仍保留。

## 仍需明确的边界

持续媒体连接正常时，新节点由服务器编入同一音频流，不依赖游客小程序 JS 或 WebSocket 在息屏时执行。司机必须持续上报有效位置，路线必须有对应语言的可用音频。

媒体连接因断网、服务重启或系统终止而消失后，处于冻结状态的小程序 JS 无法保证自动重建连接。本轮修复的是返回前台后能丢弃失效会话并重试恢复，不能据此承诺锁屏期间断线无缝自愈。

自动化环境模拟支付宝原生播放器回调，无法验证所有手机的后台策略，也无法完全模拟无媒体来源标识的迟到原生事件。长时间静音后仍持续读取媒体、锁屏按钮实际行为和设备最终出声仍需两类手机验证。
