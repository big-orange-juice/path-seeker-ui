## 5. 关键锁屏媒体：每轮约 16 分钟

退出房间并结束导览音频。两部手机分别开始“手动触发”，电脑开两个独立控制标签页，标清 Android / iPhone。启动后尽快锁屏，整个会话最多 20 分钟。

以锁屏时间为起点，电脑操作人临时选择声音，不提前在手机排好。全程不解锁、不点通知或锁屏播放键。

| 编号 | 时间 / 操作 | 通过条件 | 记录 |
| --- | --- | --- | --- |
| L1 | 锁屏约 1 分钟，Android 发三声、iPhone 发两声 | 各自听到对应声音，无串音 | 点击 / 出声时间 |
| L2 | 此后保持静音，锁屏约 6 分钟再随机发声 | 静音约 5 分钟后仍自动出声 | 同上 |
| L3 | 再保持静音，到锁屏约 15 分钟随机发声 | 两端黑屏时直接出声 | 同上 |
| L4 | 各间隔 5 秒再发两组不同声音 | 顺序正确，每组一次，不是解锁后补播 | 同上 |
| L5 | 仍锁屏，在电脑结束本轮 | 本轮不能再触发；解锁后可结束页面并新建 | 同上 |

必须记录手机实际发声，不能以 `sentBytes`、网页“已加入媒体流”或播放器时间代替。记录点击到出声的延迟；延迟超过现场可接受值应另记问题，最终有声音不等于实时体验达标。

若 `lastHeartbeatAt` 锁屏后不再更新，但 L2 / L3 仍出声，支持“无需持续执行 JS”。若心跳一直运行，只能说明该设备本轮锁屏成功。

解锁后才响、需要点继续、只有旧缓存声、单端成功均不满足双端要求。失败至少换新会话复测一次。定时模式可补测第 1 / 5 / 15 分钟，但不能替代随机插音排除预缓存。

## 7. 正式锁屏到站仍需单独验收

L1–L5 通过只说明持续媒体在设备上可用。**正式路线当前没有接入这条持续流，不能据此宣布锁屏进入 B / C 自动播放讲解已经实现。**

当前可记录一次对照：司机持续上传，游客亮屏验证 A → B；另开未完成的测试行程，A 播放后锁游客手机，由司机实际进入 B / C，记录是否到解锁才触发。此项是现状记录，不能保证通过；旧流程仍可能因 JS 暂停而不能发起下一段。

最终标准必须包含：司机真实进入范围 → 服务端收到新鲜位置并只触发一次 → 实际节点讲解进入当前流 → 两端无需解锁听到正确内容 → 游览进度正确。提示音、预先排好的音频和服务器日志不能替代整条链路。

## 8. 失败记录模板

失败后先在电脑下载服务器记录，再解锁手机刷新并复制诊断，最后再重试。

| 字段 | 填写内容 |
| --- | --- |
| 用例 / 手机 / 网络 | 如 L3 / iPhone 型号 / 蜂窝 |
| 会话 ID | 控制台字符串 ID，不附控制口令 |
| 开始 / 锁屏 / 触发 / 出声时间 | 精确到秒；没响写“未听到” |
| 屏幕状态 | 全程锁屏 / 自动亮屏 / 手动解锁 |
| 服务器状态及最后 JS 心跳 | 原样记录，说明是否解锁后才恢复 |
| marker.queued / marker.emitted | 是否存在及时间 |
| 附件 | 服务器 JSON、手机诊断 JSON、另一设备录像 |

没有 queued 查控制请求；入队未 emitted 查服务器；连接中断查网络；持续发送但手机不响查原生播放器 / 系统。没有司机新位置先查定位通道。
