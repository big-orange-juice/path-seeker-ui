# 43 · Web-Admin 导游认知可用性优化计划

> 状态：**Phase A / B / C 已落地**（B-3 路线行「主按钮 + 更多」按需求保持现状未改）  

> 日期：2026-07-23  
> 范围：`apps/web-admin` 文案、表单、列表展示、可隐藏复杂度  
> 用户画像：旅行社导游为主（技术词认知度低）；同时保留面向国际用户的英文品牌与关键英文入口  
> 关联：`docs/41-route-status-workflow.md`、路线详情左中右工作台、导游管理、主体/馆藏管理

---

## 1. 目标

1. **降低导游上手负担**：少填技术参数、少见研发话术、少用协议式表单。
2. **措辞贴近业务**：用「博物馆 / 这一站 / 声音样本」等业务词，替代「主体 / 语义资料」等抽象词（**状态类除外，见硬约束**）。
3. **无伤大雅地藏复杂度**：默认路径只暴露常用能力；高级/技术字段折叠或仅管理员可见。
4. **不破坏既定产品与契约**：状态机、路线编辑布局、英文品牌均保持。

### 1.1 非目标（本计划明确不做）

- 不合并、不简化、不改写 **发布状态 / 审核状态** 的维度与文案
- 不改路线 **编辑 Dialog 的左中右布局**（Flow + 手机预览 + 对话）
- 不去掉面向国际用户的 **英文品牌与登录侧英文标识**
- 不重做权限矩阵与后端工作流（仍以 `docs/41` 与 `routeWorkflow.ts` 为准）
- 不把 H5 / 模拟器视觉纳入本计划

## 2. 硬约束（评审已确认）

| # | 约束 | 说明 |
|---|------|------|
| C1 | **状态严格对齐后端** | `publishStatus`、`auditStatus`、`auditRequired` 及列表双筛、双标签、筛选选项文案 **保持现状**，与 `docs/41` / `ROUTE_*_STATUS_OPTIONS` / `getRouteStatusPresentation` 一致 |
| C2 | **状态文案不改** | 「未上架 / 已上架 / 已下线」「未提交 / 待审核 / 已通过 / 已驳回」「需审 / 免审」等 **不得合并、不得改写** |

| C4 | **英文保留** | 顶栏 `Path Seeker`、`path seeker museum`、登录页 `Admin sign in` 等 **保留**；中文业务文案可并行优化，不做「全中文化」 |

## 3. 原则

1. **状态展示 = 后端真相**：只优化「怎么解释下一步」，不优化「状态叫什么」。
2. **布局不动、话术可润色**：路线工作台结构已定稿；降低认知靠副文案与引导，不靠改骨架。
3. **默认简、高级全**：导游默认表单短；编码、经纬度、最大查询数、管道符结构等进高级或可视化。
4. **错误只说结果与下一步**：不把角色权限矩阵、token、接口语义甩给用户。
5. **中英分工**：品牌/登录装饰可英文；**操作按钮、表单标签、空态、确认框** 以清晰中文（或中英并列）为主，避免关键操作只有英文缩写。

## 7. 验收标准

| 场景 | 通过条件 |
|------|----------|
| 状态一致性 | 与后端字段、筛选、标签文案 **像素级语义一致**（相对现状无合并/无改字） |
| 路线详情 | 仍为左 Flow / 中预览 / 右对话；仅文案变化可被接受 |
| 英文 | 品牌与登录英文标识仍在 |
| 导游新建路线 | 不接触「最大查询数」即可完成对话或按条件生成 |
| 导游改选择题 | 不需理解「标识 \| 文案」即可改选项与正确答案 |
| 导游建形象 | 理解「声音样本 / 文风示例」，无语义/multipart 术语 |
| 错误提示 | 无 token、无长权限矩阵；用户知道下一步 |
| 空菜单 | 不出现无说明空白页 |

## 8. 风险与注意

1. **文案替换范围**：`主体` 可能出现在类型名、注释、测试；UI 与用户可见串优先，代码标识符可不改。  
2. **字段改名 vs 标签改名**：表单 label 可改中文；提交 JSON 字段名不变。  
3. **可视化选项编辑**：需兼容已有 `options` / `correctOptionId` 结构，保存前后 round-trip。  
4. **隐藏最大查询数**：确认默认值与后端 `maxNodes` 默认一致（当前表单 clamp 35–50）。  
5. **状态相关任何 PR**：自检对照 `docs/41` 与 `routeWorkflow.ts`，禁止顺手「优化」状态文案。

## 11. 一句话结论

在 **状态与后端严格一致、状态文案不动、路线编辑左中右布局锁定、英文品牌保留** 的前提下，通过 **业务化菜单与表单命名、隐藏技术参数、节点可视化编辑、错误/锁态口语化、空模块治理**，把导游主路径从「会操作系统」降到「会改讲解并上架」。
