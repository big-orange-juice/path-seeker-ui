# Path Seeker B 端产品方案

> 产品名称：Path Seeker / 秘径寻踪  
> 产品形态：博物馆内容与路线运营管理后台  
> 文档状态：V1.0 评审稿  
> 适用对象：博物馆管理员、策展人、内容编辑、导游/讲解员、运营人员、审核人员、研发与测试

## 1. 产品定义

### 1.1 产品定位

Path Seeker B 端是面向博物馆运营团队的内容资产化和路线运营工作台。它把博物馆、楼层展厅、地图点位、展品资料、导游角色、解说素材、谜题节点、奖励和游客数据组织为可复用对象，并通过“创作—校验—审核—发布—复盘”的闭环支撑 C 端现场体验。

B 端不是简单的后台 CRUD。核心任务是把一件展品可靠地转化为一段可听的解说、一个可验证的互动节点和一条可执行的现场路线，同时保证每次发布都可追溯、可回退、可复盘。

### 1.2 解决的问题

| 业务问题 | B 端产品回应 |
| --- | --- |
| 场馆、展厅、展品资料分散 | 统一博物馆、地图、点位和馆藏对象，建立关联关系 |
| 内容编辑与路线编排反复录入 | 展品、解说、导游、题型和奖励资产化复用 |
| AI 生成效率高但质量不可控 | Agent 只生成草稿，提供来源、预览、异步状态和人工确认 |
| 音频生产链路长、失败难追踪 | 统一素材上传、ASR、风格分析、音色克隆、TTS 和试听状态 |
| 多角色协作容易误改或越权 | 明确归属、编辑锁定、审核锁定和发布权限 |
| 上线后不知道路线是否有效 | 用开始、完成、站点流失和内容质量指标驱动迭代 |
| 现场问题无法反馈给内容团队 | 把用户评价、反馈、问答异常和生成失败纳入处理闭环 |

### 1.3 产品目标与非目标

**产品目标**

1. 新建一条 5 站点路线，从选题到可提交审核不超过 30 分钟（不含素材生成等待）。
2. 所有上架路线通过统一的结构、内容、素材、现场点位和权限校验。
3. AI 生成内容可被逐站点预览、编辑、追溯和重试，不能静默覆盖人工内容。
4. 管理人员能在 5 分钟内发现异常路线、低完成站点和失效音频。
5. 所有创建、修改、审核、发布、下线和删除动作有操作者、时间、版本和变更摘要。

**本期非目标**

- 不替代博物馆专业内容审校流程，不自动判断历史事实真伪。
- 不把自然语言 Chat 作为唯一的后台操作入口；关键字段仍需结构化表单和明确状态。
- 不在首版建设完整的营销投放、票务、会员和商业结算系统。
- 不承诺所有 AI 生成内容无需人工即可发布。

## 2. 用户、角色与权限

### 2.1 现有角色基线

| 角色 | 代码基线 | 主要任务 | 权限原则 |
| --- | --- | --- | --- |
| 管理员 | ADMIN | 场馆配置、全局内容治理、审核、上架/下线、账号与权限 | 可查看全局；可上架/下线任意路线；删除原则上仅限创建人本人 |
| 内容创建者/导游 | CREATOR | 创建导游、编辑自己的路线和站点、提交审核 | 只编辑本人路线；已上架或待审核内容锁定；审核通过后可申请上架 |
| 游客 | C 端用户 | 使用已发布路线 | 不进入后台；仅产生游玩、评价和反馈数据 |

当前实现以 ADMIN 与 CREATOR 为最小可用权限集合。运营专员、审核员、数据分析员等角色可在 V1.1 细分，但不能通过前端隐藏按钮代替服务端鉴权。

### 2.2 建议角色扩展

| 角色 | 适合团队 | 推荐权限 |
| --- | --- | --- |
| 场馆管理员 | 馆方负责人 | 博物馆、用户、全局发布和权限 |
| 策展编辑 | 内容团队 | 展品、故事、站点、解说草稿 |
| 音频制作 | 讲解/制作团队 | 导游、素材、音频生成和发音 |
| 路线运营 | 活动运营团队 | 路线投放、海报、数据、下线 |
| 内容审核 | 专家/馆方审核 | 只读查看待审核内容、通过/驳回 |
| 数据分析 | 运营分析团队 | 看板、明细和导出，不可改内容 |

扩展角色必须以资源和动作授权为粒度，至少区分查看、编辑、提交审核、审核、发布、下线、删除、导出。

## 3. 业务对象与状态

### 3.1 核心对象关系

    博物馆
      ├─ 楼层 / 展厅 / 设施
      ├─ 展厅地图 ─ 点位 ─ 展品
      ├─ 导游 ─ 音色 / 风格 / 发音词典
      ├─ 馆藏展品 ─ 标签 / 素材 / 问答来源
      └─ 主题路线
           ├─ 背景故事
           ├─ 路线站点（route_stage）
           │    ├─ 展品 / 点位
           │    ├─ 解说 / 音频
           │    ├─ 玩法配置
           │    └─ 奖励 / 解锁规则
           └─ 海报 / 发布版本 / 运营数据

### 3.2 关键状态

| 对象 | 状态 | 说明 |
| --- | --- | --- |
| 路线发布 | 未上架、已上架、已下线 | 决定 C 端是否可发现和加入 |
| 路线审核 | 未提交、待审核、已通过、已驳回 | 仅需审核的创建者路线使用 |
| 生成任务 | 空闲、排队中、执行中、等待重试、成功、失败、取消 | 适用于路线、解说、音色、图片和海报 |
| 导游 | 草稿、可用、异常、停用 | 音色状态与资料状态分开 |
| 音频 | 未生成、生成中、可播放、过期、失败 | 文本更新或更换导游后需标记失效 |
| 地图/点位 | 草稿、可用、停用 | 停用点位不能作为新路线发布依赖 |
| 反馈/评价 | 待处理、处理中、已回复、已关闭、已驳回 | 处理人和回复记录可追踪 |

### 3.3 路线工作流

发布状态与审核状态分离，避免“审核通过”被误解为“已经对游客开放”。

    创建
      -> 未上架 / 未提交
      -> 待审核
      -> 未上架 / 已通过
      -> 已上架
      -> 已下线
      -> 重新编辑 -> 重新审核（如内容发生影响审核的变更）

- 管理员创建的路线默认可配置为免审，但仍必须通过发布前质量校验。
- 内容创建者只能编辑本人未上架或已下线路线；待审核和已上架路线锁定。
- 管理员可以审核、上架或下线任意路线；他人未上架路线原则上不开放编辑。
- 删除采用软删除并保留审计；已上架路线删除前必须先下线。
- 已上架路线的内容修改采用“下线—编辑—重新审核—再上架”，不直接修改线上版本。

## 4. 信息架构

### 4.1 一级导航

| 模块 | 业务心智 | 当前页面/能力 |
| --- | --- | --- |
| 运营分析 | “现在运营得怎么样” | 总用户、展品、路线、发布、场次、完成率和路线表现 |

| 馆藏内容 | “有哪些可用内容资产” | 展品列表、详情、编辑、标签、关联位置与路线 |
| 展厅地图 | “游客能不能找到” | 地图、展厅、点位、坐标和点位-展品关系 |
| 导游管理 | “谁在讲、用什么声音讲” | 导游角色、风格参考、素材、音色生成、试听 |
| 主题路线 | “如何把内容编成体验” | 路线、故事、站点、玩法、预览、审核、发布、海报 |
| 发音词典 | “专有名词能否正确播报” | 词条、拼音、共享范围、音频状态、冲突处理 |
| 用户管理 | “谁在使用平台” | C 端用户、管理员、角色、状态和登录信息 |

藏品、徽章、标签、海报、评价、反馈和任务中心既是独立业务对象，也是路线工作台的关联能力；首版可从关联详情进入，V1.1 再提供独立菜单。

### 4.2 统一页面结构

所有后台页面保持相同骨架：页面标题与范围说明、筛选栏、主列表、批量或行级操作、分页、详情/编辑对话框、状态反馈和刷新入口。创建与编辑优先使用对话框或工作台，不在列表页堆叠长表单。

## 5. 端到端业务流程

| 阶段 | 负责人 | 主要动作 | 出口 |
| --- | --- | --- | --- |
| 场馆准备 | 管理员 | 创建博物馆、楼层、展厅、设施和地图 | 游客可用基础位置 |
| 资产整理 | 内容编辑 | 导入/维护展品、图片、年代、材质、标签、来源 | 展品可检索、可关联点位 |
| 导览准备 | 导游/音频制作 | 创建导游、上传风格和音频素材、生成音色、试听 | 导游可被路线选择 |
| 选题组卷 | 策展/运营 | 选择主题、适龄、难度、时长和展品范围 | 路线草稿 |
| 内容生成 | 编辑 + Agent | 批量生成站点、解说、题面、图片和海报 | 可编辑的生成草稿 |
| 路线编排 | 内容编辑 | 调整站点顺序、必做状态、点位、玩法和分值 | 路线结构完整 |
| 内容校验 | 编辑/审核员 | 检查事实来源、答案依据、音频、点位、适龄和安全提示 | 校验通过 |
| 审核发布 | 管理员 | 审核、通过/驳回、上架、下线、回滚 | C 端可见版本 |
| 运营复盘 | 运营/分析 | 查看开始、完成、站点流失、问答和反馈 | 形成调整任务 |
| 内容迭代 | 原创建者/管理员 | 下线后编辑并重新审核 | 新版本上线 |

## 6. 功能方案

### 6.1 运营分析

**目标**：用一页看清平台规模、内容供给、游客使用和路线质量，支持从指标下钻到路线或站点。

**P0 功能**

- 指标卡：用户总数、展品总数、路线总数、已发布路线、游玩次数、完成场次、完成率。
- 时间范围、博物馆和路线筛选。
- 路线开始/完成趋势图，支持按路线查看明细。
- 异常提示：完成率过低、站点无完成、音频失败、生成任务积压。
- 刷新、加载、空状态和错误状态。

**P1 功能**

- 路线漏斗：曝光、详情、加入、首站完成、路线完成。
- 站点流失热力、提示使用率、问答解决率、平均耗时。
- 资产复用率、发布周期、审核驳回原因。
- 明细导出和按天/周/月对比。

**验收**：看板数字必须显示统计口径和时间范围；每个可点击指标都能落到对应列表；无数据时不显示误导性的 0 环比。

### 6.2 博物馆、楼层与设施

**博物馆字段**：名称、编码、地址、简介、开放时间、闭馆日、联系电话、封面、状态、默认语言。

**楼层字段**：楼层名称、楼层编号、排序、面积、开放状态、默认地图。

**设施字段**：设施类型、名称、所在楼层/展厅、坐标、服务说明、开放状态。设施类型至少覆盖入口、卫生间、服务台、电梯、楼梯、休息区和出口。

操作规则：

- 新建博物馆后才能建立楼层、地图和展品归属。
- 停用博物馆前提示受影响的公开路线和点位；有线上路线时禁止直接删除。
- 变更开放信息和闭馆日要记录修改人和生效时间。
- 地图和路线引用停用楼层时，发布校验必须阻塞。

### 6.3 馆藏内容（展品）

**列表能力**：按博物馆、展厅、名称、编码、年代、材质、类别、重点类型、标签和状态筛选；支持分页、批量导入预留和结果统计。

**详情与编辑**：

- 基础资料：名称、别名、编码、年代、材质、尺寸、来源、摘要、详细说明。
- 多媒体：主图、细节图、视频、版权和来源。
- 位置：博物馆、楼层、展厅、地图点位，可关联多个点位。
- 运营字段：推荐停留时长、适龄、可用于路线、问答可见性。
- 内容质量：事实来源、最近审核时间、待补字段和引用路线。
- 标签：主题、时代、材质、难度、路线用途。

删除和停用必须展示影响范围：被哪些路线站点引用、是否被问答使用、是否存在公开收藏卡。被线上路线引用的展品不得静默删除，只能停用并进入影响处理。

### 6.4 展厅地图与点位

地图工作台支持按博物馆、楼层、展厅选择地图，展示底图、点位、设施和点位-展品关系。

**点位编辑字段**：点位名称、编码、x/y 坐标、展厅、楼层、现场提示、推荐停留时长、关联展品、可用状态。

**校验规则**：

- 坐标必须在底图边界内；同一地图的点位编码不可重复。
- 点位关联展品时，展品必须属于同一博物馆；跨馆关联阻塞保存。
- 点位被路线引用时，修改坐标需显示影响路线并写入变更摘要。
- 软删除点位前必须提示关联站点；线上路线引用时只能停用或走下线流程。
- 地图保存后提供手机预览，验证缩放、标记和文字在移动端不重叠。

**P1**：支持点位批量导入、坐标校准、版本对比、地图覆盖物导出和现场扫码核验。

### 6.5 导游、风格与音色

导游是 C 端的内容角色，也是路线的语音和语气来源。

**基础资料**：名称、头像、简介、适用人群、讲解风格、标签、状态、可见范围、创建人。

**风格参考**：支持 TXT/文稿等参考材料，解析为风格描述和结构化画像；保留原文件、解析时间和解析失败原因。

**音色生产**：

1. 上传音频或视频素材，校验格式、时长和版权确认。
2. 对视频提取音频，进入 ASR 转写。
3. 生成风格分析和音色克隆任务。
4. 展示任务状态、进度、重试次数、失败原因和下一次运行时间。
5. 生成完成后试听，确认语言、语速、音量、音调和适用场景。
6. 发布为可供路线选择的音色；变更导游或文本后标记旧音频过期。

**状态要求**：资料状态、音色状态和生成任务状态分开显示。生成中锁定影响字段，但不阻塞查看和取消；失败允许按原因重试，不允许连续重复提交。

**权限**：管理员可试听全部导游；创建者只能试听管理员创建或本人创建的导游；C 端只看到公开且可播放的导游。

### 6.6 主题路线工作台

#### 6.6.1 路线基础资料

字段包括：路线编码、标题、主题、博物馆、封面、导游、适龄、难度、路线规模、预计时长、是否支持组队、队伍人数、简介、奖励标题、排序、发布和审核状态。

新建路线提供两种入口：

- 手动创建：先填基础资料，再添加站点；
- 按主题生成：输入主题、展品筛选、适龄、难度、站点数和最大节点数，由 Agent 生成草稿。

#### 6.6.2 站点编辑器

每个 route_stage 节点至少包含：站点编号、顺序、标题、副标题、交互类型、关联展品、关联点位、解说、玩法配置、解锁规则、是否必做、分值、下一步规则。

工作台支持：

- 新增、复制、编辑、删除和批量删除站点；
- 拖拽或精确列表重排；
- 节点在同一或不同路线间移动，并显示影响；
- 绑定/解绑展品、地图点位、导游和解说；
- 预览站点在 C 端的观察、解说和题面；
- 查看当前站点的生成任务、音频和图片状态；
- 对 8 类固定题型提供配置校验和预览；
- 维护路线背景故事和章节过场。

#### 6.6.3 8 类玩法配置

| 类型 | 配置重点 | 发布前校验 |
| --- | --- | --- |
| observe_choice | 观察点、选项、正确项、解析 | 至少 1 个正确项；答案依据非空 |
| clue_find | 图片、热点区域、命中条件 | 热点在图片范围内；至少 1 个命中点 |
| sort | 元素、正确顺序、关系说明 | 元素不重复；顺序长度一致 |
| match | 左右项、正确映射、错误提示 | 两侧数量和 key 可匹配 |
| image_puzzle | 碎片、槽位、完成条件 | 素材完整；碎片数量合法 |
| story_branch | 分支文案、后果、事实解析 | 每个分支都有结果，不能只写“正确/错误” |
| multi_step_reasoning | 证据、推理链、结论 | 证据可追溯；结论至少一个 |
| code_break | 密码片段、输入规则、解锁结果 | 密码规则、错误上限、提示策略完整 |

#### 6.6.4 预览、校验和发布

路线预览必须模拟移动端完整链路：路线详情、地图、站点观察、解说、谜题、结果和结算。预览数据不能发放真实奖励，也不能污染游客统计。

发布前自动校验分四层：

1. **结构**：至少一个必做站点，顺序连续，下一步规则无死链。
2. **内容**：标题、故事、题面、答案、解析、适龄和难度齐全。
3. **现场**：展品、点位、楼层、地图和现场提示有效。
4. **媒体**：封面、图片、文字、音频可访问，音频与当前导游/文本版本一致。

校验结果分为阻塞、警告和建议。阻塞项未修复不能提交审核或上架；警告必须由操作者确认。

### 6.7 Chat / Agent 对话式创作

Chat 用于减少检索、组卷、站点生成和批量改写的操作成本，但所有会改变数据的动作必须有上下文和确认。

**上下文**：当前管理员、博物馆、路线、选中站点、相关展品和当前版本。上下文变更需在消息区显式展示。

**可执行意图**：

- 检索展品、路线和站点；
- 按主题生成路线草稿；
- 批量生成站点或解说；
- 新增、编辑、删除、重排站点；
- 切换导游、生成音频或配图；
- 预览、执行发布前校验、提交审核；
- 查询异步任务状态。

**交互规则**：

1. 先返回计划或影响范围，再执行批量或破坏性操作。
2. 删除、上架、下线、覆盖批量内容和切换导游必须二次确认。
3. SSE 流式显示文字、工具调用、任务进度、警告和错误；不能用无反馈的长请求。
4. 生成结果写入草稿并标记 AI 来源、生成时间和使用的素材版本。
5. Agent 不可虚构展品、年代、点位或答案；检索不到时返回待补资料。
6. 任务失败显示可操作的原因、重试入口和是否已产生部分结果。
7. Chat 完成后增量刷新路线、站点或素材，不强制整页刷新。

### 6.8 解说、音频与发音词典

**解说流程**：生成初稿 → 编辑正文 → 选择导游 → 生成音频 → 试听 → 发布到站点。文本变更、导游变更或发音词典变更都会使旧音频进入“待重新生成”。

**批量任务**：支持按路线或站点批量生成，显示总数、成功数、失败数、当前任务和重试入口；任务运行时允许查看，不允许修改同一产物的关键输入。

**发音词典**：

- 词条、拼音/多音字、替换规则、适用范围、来源、版本、状态；
- 共享词典、导游专属词典和路线临时词典分层；
- 冲突时显示命中层级和最终播报结果；
- 词条发布后影响范围可追踪，过期音频可集中刷新；
- 词典只存明确可验证的读音，不让模型自由猜测。

### 6.9 海报、收集品、徽章与标签

这些对象既用于 C 端体验，也用于运营配置。

- **海报**：路线封面、分享卡、打印投放版本；支持手工上传和自然语言生成，生成后需审核和绑定路线。
- **收集品**：印章、碎片、角色卡、文物卡；定义名称、图像、描述、获得条件和发放规则。
- **徽章**：定义触发条件、展示顺序、图标、文案和有效期；支持补发和撤销，但要记录原因。
- **标签**：维护主题、时代、材质、适龄、难度等分类；支持对展品、路线和谜题批量设置。

删除或修改已经发放的收集品、徽章时，必须提示对 C 端历史结果的影响；历史结算应保留当时的文案和图像快照。

### 6.10 用户、管理员与账号安全

**C 端用户管理**：按用户编号、昵称、注册渠道、状态、注册时间和最后登录筛选；查看资料、路线历史、完成情况和反馈。启用/禁用/逻辑删除均需权限和二次确认，不能修改游客的游玩结果。

**后台账号**：支持创建、详情、资料、角色、启停、强制重置密码、当前账号改密、注销和逻辑删除。管理员不能删除自己或绕过权限删除更高权限账号。

**安全要求**：

- 会话过期明确提示，不能展示内部错误；
- 密码不回显，重置后要求重新登录；
- 删除、发布、批量生成、导出等高风险动作记录审计；
- 所有 ID 按字符串处理，避免雪花 ID 在前端精度丢失；
- 服务端鉴权是最终边界，前端不可只靠隐藏按钮控制权限。

### 6.11 评价、反馈与问题闭环

后台支持按路线、展品、时间、评分、状态和关键词筛选评价与反馈。处理人可回复、标记处理、关闭或驳回，并保留原文、回复、时间和处理人。

问题分类建议：内容事实、点位/地图、音频、题目难度、账号、网络/性能、隐私与安全。高频问题可一键转为路线待办或展品修订任务，关联到具体路线版本和站点。

## 8. 数据质量与发布治理

### 8.1 内容质量门禁

每个可发布路线必须满足：

- 归属博物馆、楼层、展厅和地图引用有效；
- 每个必做站点有明确展品或现场目标；
- 每个谜题有答案依据、错误解析和提示策略；
- 站点顺序连续，必做节点和终点规则无死链；
- 导游、解说文本、音频和音量配置完整；
- 图片、音频、海报有版权/来源标记；
- 适龄、难度、预计时长与实际站点数量基本匹配；
- C 端预览可以从路线详情走到结算；
- 当前版本与已生成媒体版本一致；
- 发布人、审核人、时间和变更摘要可查询。

### 8.2 版本与回滚

V1 至少保存：草稿版本、待审核版本、上架版本、下线版本的版本号、创建人、审核人、时间和摘要。V1.1 增加字段级差异、版本比较和一键回滚。

回滚只恢复内容版本，不自动恢复已经发生的游客成绩和奖励；回滚后必须重新执行发布前校验，并产生新的发布记录。

### 8.3 异步任务中心

所有生成任务统一展示：任务类型、所属路线/站点/导游、状态、进度、尝试次数、最大尝试次数、错误码、错误消息、创建/开始/下次重试时间。

任务状态变化必须可被列表和详情消费；生成中对象不可重复提交同一类型任务。失败任务允许按错误类型修复输入后重试，取消任务不得伪装成失败。

## 11. 依赖、风险与验收

### 11.1 关键依赖

- 统一的博物馆、展厅、地图、点位、展品、路线和站点数据模型；
- 路线发布、审核、任务状态和权限接口；
- Agent/SSE、音频生成、图片生成和附件服务；
- C 端游玩事件、问答来源、完成结果和反馈数据；

- 审计日志、错误码、告警和任务重试机制。

### 11.2 主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| AI 生成事实错误 | C 端错误知识、品牌风险 | 强制来源和人工审核；发布门禁阻塞缺少依据的内容 |
| 点位或地图不准 | 游客现场无法完成 | 手机预览、现场扫码核验、展厅级降级 |
| 音色版权或素材质量问题 | 无法上线或产生投诉 | 上传时确认来源；导游和音频状态分离 |
| 多角色误编辑 | 内容覆盖、审核失效 | 归属权限、编辑锁、版本和审计 |
| 任务长期排队 | 编辑误重复提交 | 任务中心、进度、重试上限和超时告警 |
| 指标口径不一致 | 错误运营决策 | 事件字典、时间范围和计算口径固化 |
| 线上版本直接修改 | 游客前后内容不一致 | 上架锁定，变更走下线/新版本 |

### 11.3 V1 验收

1. 管理员可以完成博物馆—展厅—地图—点位—展品的基础配置，并在手机预览中看到正确关系。
2. 内容创建者可以创建路线、添加/重排站点、选择八类玩法并完成结构校验。
3. Agent 生成有上下文、有流式进度、有草稿标识，批量修改和删除需要确认。
4. 生成中、失败、取消和重试状态在列表与详情一致，不重复创建相同任务。
5. 待审核路线锁定编辑；审核通过/驳回后状态和可操作按钮符合角色策略。
6. 已上架路线对非创建者只读；管理员可下线并保留游客侧策略提示。
7. 发布前阻塞项、警告项和建议项清晰区分；校验通过后才可上架。
8. 运营看板能展示用户、展品、路线、发布、场次、完成率和路线开始/完成趋势。
9. 所有高风险动作可追溯到账号、时间、对象、版本和变更摘要。
10. 所有前后端 ID 按字符串传输，不发生长 ID 精度丢失。

## 13. 产品决策记录

1. 路线是 B 端最小交付单元，但路线不能脱离博物馆、点位、展品和导游独立发布。
2. 结构化编辑器是事实来源，Chat 是提效入口；两者共享同一套权限、校验和版本。
3. “已审核”不等于“已上架”，“已生成”不等于“已通过内容审核”。
4. C 端完成率是结果指标，B 端不能通过降低题目质量或跳过现场观察来追求数字。
5. AI、音频、地图和图片都是可失败的异步依赖，后台必须把失败变成可理解、可重试、可追溯的任务。
