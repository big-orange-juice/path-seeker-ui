# 支付宝小程序无声回归修复与复测

> 后续竞态复查已增加服务端修复，需要同时发布 WebAPI 和小程序。本文件的“仅发布小程序”和 418 项测试记录描述的是前一轮；最新发布与验证说明见 [竞态审计与复测](alipay-tour-audio-race-audit-2026-11-11.md)。

## 本轮范围与证据

针对“加入车夫房间后只有震动，退出房间后普通讲解也不出声”的反馈，修复小程序的播放器控制和房间清理顺序。后台持续流和司机到站判断仍然保留，`serverTourAudio` 保持 `true`。

先补回归测试，旧代码在以下五个断言中失败：

1. 问答结束后的命令出现 `release → reconnect → hold`，重连误触发旧播放器的 `interrupted`，重新把服务端挂起。
2. 暂停恢复后的命令出现 `resume → reconnect → hold`，再次进入同一静音状态。
3. 原生持续流正在播放静音、页面显示 ▶ 时，点击按钮发出了 `pause`，没有选择当前节点。
4. 原生播放器报告解码错误后，下一次成功的状态轮询把错误文字清空。
5. 退出真实房间服务时，清理回调发布了尚未移除的旧房间，页面调度器又发起新的媒体会话，退出后持续流仍然占用播放器。

修复后以上断言通过；还覆盖了暂停后选新节点、显式恢复被挂起会话、多个恢复请求共用一次重连、创建过程中退房、旧原生 Stop 事件迟到、新音源真实暂停，以及退房后直接播放普通节点音频。

播放器在前台、未暂停且未挂起时，媒体时间超过 20 秒没有前进，会显示可重试错误。静音占位也应推进媒体时间；这项检测不能判断扬声器是否真的发声。息屏期间不依赖此检测维持连接，主动暂停不会被强制恢复。

## 部署

本轮没有修改后端代码、数据库、FFmpeg 或 Nginx 配置。如果已经发布上轮正式 `/TourAudioSessions` WebAPI，本轮只需发布小程序。

在 `D:/workspace/amh/code/CulturalTourism/web/path-seeker-ui` 执行：

```powershell
pnpm --filter @path-seeker/mp-alipay build
```

构建产物位于 `D:/workspace/amh/code/CulturalTourism/web/path-seeker-ui/apps/mp-alipay/dist`。支付宝开发者工具打开该目录，上传新的体验版/发布版本；测试手机彻底退出旧版小程序后打开本次新版本，并重新加入房间。诊断记录版本字段为 `tour-audio-recovery-20261111`，可用于核对是否加载了本轮代码。

保留以下配置：

```js
background: true,
backgroundAudio: true,
serverTourAudio: true,
```

2026-11-11 只读检查正式地址 `/path-seeker/api/TourAudioSessions/invalid/media.mp3?ticket=invalid`，返回 WebAPI JSON 404“讲解会话不存在，请重新开始”。这确认该路径已路由到正式控制器，不代表有效媒体连接、FFmpeg 解码或手机播放已验收。

## 先原地测试，再去现场

Android 和 iPhone 各执行一遍，先确认设备媒体音量、蓝牙输出目标正常。选择一个已有真实音频的节点，司机开启位置共享，先暂停司机的实时讲话，以免其优先占用路线音频。

| 顺序 | 操作 | 通过条件 |
| --- | --- | --- |
| 1 | 暂不加入房间，手动点节点播放 | 听到正常讲解；进度前进 |
| 2 | 加入房间，开始游览，在尚未自动到站时点击当前节点 ▶ | 听到当前节点讲解；按钮不会把空闲静音流暂停 |
| 3 | 暂停 10 秒后恢复，再重复一次 | 每次恢复都重新出声；服务端不会被误挂起 |
| 4 | 暂停后选择另一个有音频的节点 | 新节点出声，原生播放器不会继续停留在暂停状态 |
| 5 | 播放中打开问答，再关闭；播放补充音频后返回 | 路线讲解恢复；没有两路重叠 |
| 6 | 退出房间，然后手动点击节点 ▶ | 普通节点音频正常播放；不会重新建立旧房间媒体会话 |
| 7 | 重新加入房间，在节点 A 播放时锁屏，A 结束后进入 B，再进入 C | 不解锁、不点播放，B、C 均实际出声 |
| 8 | 屏幕保持关闭，在节点外静音等待至少 5 分钟，再进入未播放节点 | 新节点实际出声 |

退房后停止依赖司机位置的自动触发，普通手动播放继续可用。现场自动到站仍需游客在车夫房间内、司机位置新鲜、开启跟随和自动播放，并关闭手动锁定内容。

## 无声时提供的诊断

播放器报错或前台卡住后，页面会保留错误文字，并提供“重试”和“复制诊断记录”。先复制记录，再重试，便于保留失败时状态。记录只包含会话标识、节点标识、媒体时间和状态、设备型号及版本，不包含游客登录凭证、媒体票据、音频 URL 或原始错误文本。

- `server.held=true`：服务端讲解被挂起，核对问答/补充内容是否仍然占用；明确点击播放会释放旧挂起状态。
- `server.paused=true` 或 `player.nativePaused=true`：暂停状态。
- `server.stageId` 为空且队列为空：没有待播放节点；先手动选择一个节点验证音频，再核对司机定位与触发范围。
- `server.roomAudioPlaying=true`：司机讲话/翻译优先，暂停司机实时讲话后验证路线节点。
- `server.hasError=true`：服务端出现音频读取/位置/进度等错误；结合页面错误和会话 ID 查 WebAPI 日志。
- `server.sentBytes` 增长、`player.time` 一直为 0：服务端在发送数据，但手机端没有开始推进播放；进一步检查播放器错误、网络代理或格式兼容性。
- `player.time` 前进但听不到：继续检查当前节点、司机讲话优先状态、系统媒体音量和输出设备。时间前进本身也可能只是在播放静音占位。

锁屏卡片出现、显示节点名、震动、服务端发出字节或自动化测试通过，都不能单独证明手机已发声。截图里异常大的总时长也不能作为节点讲解时长或播放成功依据，页面进度使用服务端当前讲解段时长。
