# 支付宝锁屏组件深挖与项目完成状态

实施更新：下文的完成状态表记录调研当天情况。正式 `/TourAudioSessions`、到站判断、真实讲解编排和小程序入口现已实现，当前 `serverTourAudio=true`，详见 [正式持续讲解部署与验收](alipay-server-tour-audio-deploy-test.md)。锁屏组件的开放性结论未变，双端实际锁屏出声仍须真机验收。

## 目标与本次结论

游客只使用支付宝小程序，Android 与 iPhone 均须在手机真正锁屏、屏幕关闭后，自动听到随后触发的新节点讲解。游客不点击卡片、不解锁；车夫 APP 可以在后台上报位置，服务端可以负责范围判断与媒体编排。

本次追到了支付宝客户端团队的原始文章，确认锁屏组件确实存在，而且文章明确邀请外部业务合作。这是一条值得跟进的原生能力线索。但公开资料尚未提供普通文旅小程序可直接调用的接入接口，也没有证明 Android 与 iPhone 真正黑屏时均可接收并播放新节点音频。

应继续追查的是听书业务使用的原生后台媒体能力及其接入资格。锁屏界面、支付宝宿主后台任务、小程序 JS 调度、原生音频播放需要分别核实，不能相互代替。

本次没有得到真机结果，没有接入锁屏组件，也没有完成正式连续流控制器。不能据此宣称息屏问题已经修复。

## 1. 原始文章明确说了什么

原始来源：[《频繁解锁太麻烦？支付宝实现锁屏组件新能力》](https://juejin.cn/post/7278883071515901993)，账号“支付宝体验科技”，2023-09-15。编者按明确作者为蚂蚁集团客户端工程师博欢。

可直接读取的转载：[阿里云开发者社区版本](https://developer.aliyun.com/article/1588978)，2024-08-18，转载账号“码农小达人”，注明来源“支付宝体验科技”。转载日期不应当作能力首次发布或最近升级日期。

原文第 9 节：

> 目前整个锁屏组件正在对接支付宝运动，听书业务。同时也可以接入其他支付宝外部的业务。

第 6 节还讨论了听书小程序与出行码的优先级，并把音频播放类定义为可较长时间停留的常驻业务。这支持继续追查对外合作及音频场景，但没有证明任意小程序已经具有这套能力。

原文需要保留的限制：

- 展示效果明确标注为测试 case，“非正式上线效果，仅展示接入效果”。不能据此声称听书或运动已在当前所有支付宝版本中完成上线。
- 技术实现是 Android `BroadcastReceiver`、`Activity`、`WindowManager`、`WakeLock`；没有同一套 iOS 接入实现。
- 注册接口为 Java `registerCustomHandler(LockScreenCustomInterface)`，数据由 `BgServiceDataManager` 管理。没有给出小程序 JS API、插件 provider、开放平台申请表或可以直接导入的外部 SDK。
- `onUpdateData` 默认每秒更新，是该原生设计中的回调；没有说明普通小程序的 JS 引擎会因此获得持续调度。
- `onHide` 被定义为手机再次息屏、锁屏组件隐藏。原文没有承诺隐藏期间业务网络与音频回调的行为。
- 悬浮窗演示围绕“息屏后按电源键再次展示”展开；耗电实验是持续亮屏 30 分钟。它不能证明放进口袋真正黑屏 30 分钟仍能自动起播新内容。
- 原文末尾公开邮箱用于招聘，不是锁屏能力接入支持渠道。本次未向任何作者、客服或商务发送消息。

因此，本次能确认的结论是“原生能力存在，并曾招募外部业务”，当前尚不能确认“本项目可直接调用”“黑屏时可以执行任意业务”或“iPhone 同样支持”。

## 2. iPhone 锁屏卡片与桌面组件

[Apple：Displaying live data with Live Activities](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities) 明确说明：

> Each Live Activity runs in its own sandbox, and, unlike a widget, a Live Activity can’t access the network or receive location updates.

Live Activity 可以由 APP 或 ActivityKit 推送更新。卡片持续显示、服务器推送更新卡片，不等于小程序 JS 持续运行，更没有自动获得后台启动音频的能力。文档的实现单位是 APP 的原生 widget extension；本次没有找到支付宝向普通文旅小程序开放同等 ActivityKit 接口的文档。

[Apple：Keeping a widget up to date](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date) 描述系统管理的刷新与预算，不能把桌面组件当成持续运行进程。

另查到 [mPaaS 蚂蚁动态卡片简介](https://help.aliyun.com/zh/document_detail/337813.html)。官方定义是 Native 高性能渲染引擎及应用开发技术栈，卡片嵌入原生 Native 页面，Android/iOS 具有一致性。该页没有授予支付宝小程序系统锁屏、后台音频或持续执行权限；不能因为名称有“动态卡片”就当作本需求的锁屏组件接口。

## 3. 是否有可实际接入的其他原生音频入口

### 3.1 官方后台播放器

[支付宝：my.getBackgroundAudioManager](https://opendocs.alipay.com/mini/00bifu) 是公开后台音频入口，支持离开小程序后继续播放，需要真机验证。

[BackgroundAudioManager 概览](https://opendocs.alipay.com/mini/08i49n) 说明单例、设置源自动起播及系统控制事件，但本次没有找到连续 MP3、audio-only HLS、长静音保持与锁屏断网恢复的完整兼容承诺。不能把其他平台的 `protocol: 'hls'` 属性直接视为支付宝支持。

持续媒体方案的推断是：游客前台点击开始后，原生播放器始终消费同一个媒体源；服务端把新节点讲解放进后续媒体时间线。上一段结束后流仍继续，不再依赖游客 JS 的 `onEnded` 去设置下一段源。

这是基于原生后台播放与流媒体的架构推导，尚不是网上找到并经 Android、iPhone 真机复现的支付宝解决方案。长流、静音与网络恢复仍待验证。

### 3.2 mPaaS 实时音视频原生插件

| 文档 | 已直接核实 | 仍需核实 |
| --- | --- | --- |
| [快速开始](https://help.aliyun.com/zh/document_detail/372592.html) | 支付宝小程序间及与其他应用间一对一、多对多通话；先订购并关联插件；provider 为 `2021002126663572` | 当前文旅类目能否实际订购，是否需定向授权 |
| [集成插件](https://help.aliyun.com/zh/document_detail/372593.html)、[组件功能](https://help.aliyun.com/zh/document_detail/372594.html) | 原生插件的 `rtc.start/join` 与多种组件形态 | 真正锁屏后的会话存活、后台音频策略 |
| [Config 参数](https://help.aliyun.com/zh/document_detail/372601.html) | `roomType=2` 为纯音频，含签名与音视频控制参数 | 未读到两端黑屏、后台保持的保证或相应开关 |
| [支付宝获取插件](https://opendocs.alipay.com/mini/plugin/plugin-order) | 实名主账号进入对应小程序的开发/插件服务，订购并关联 | 未登录公开页面不能确认该插件目前对本项目可购 |

原生纯音频会话提供另一个候选：把讲解作为会话中的新媒体送到游客，减少后台切文件对 JS 的依赖。服务端发布或媒体注入接口、长时间静音、自动重连与两端锁屏支持尚未形成已验证闭环。

需要区分旧版 [支付宝 rtcroom 接入介绍](https://opendocs.alipay.com/mini/introduce/vrgygu)：该页写明主要面向内部一二方、评估后暂时定向开放第三方，并要求工信部视频通话 B22 证。不能在没有依据时把这套条款全部套到上述另一代 mPaaS 插件上。

[ZEGO 支付宝 SDK 集成](https://doc-zh.zego.im/real-time-voice-miniprogram/quick-start/alipay/integrating-sdk) 同样要求联系支付宝商务开通权限、取得 MRTC 参数和挂包。第三方 SDK 不能自行赋予支付宝宿主权限。其 [后台运行 FAQ](https://doc-zh.zego.im/faq/audio-video-background-keep-alive) 标明 Android 原生平台，修改 Manifest 与 Service 的方法不能直接写进普通支付宝小程序。

## 4. WSS 与 JS 的判断

[支付宝小程序接入常见问题](https://opendocs.alipay.com/support/01rb2s) 明确回答：

> 小程序不可以延长后台保活时间和取消后台保活。

这不表示每台手机锁屏瞬间 JS 都同时停止；它表示普通小程序没有任意延长后台运行的公开保证。WSS 尚未断开、TCP 存活或协议级 Ping/Pong 都不能证明业务 JS 回调继续执行。

本次检查 [支付宝公开 API 总览](https://opendocs.alipay.com/mini/api/vzt2xm)，未找到锁屏组件、Live Activity 或后台保活的普通小程序接入条目。这只说明本次检查的公开目录没有找到，不能扩大为不存在内部、白名单或定向合作能力。

如果游客 JS 已停，服务端范围判断加 WSS 推送仍然不足；原生播放器或原生通话组件必须能够独立接收后续媒体。

## 6. 路线选择与最低验收

锁屏组件路线的下一项有效证据是可调用的接口、白名单/插件入口、当前类目资格及两端支持表。应指向原文的客户端锁屏组件团队与听书后台媒体团队，而不能仅询问通用 WSS 如何保活。

在取得该接口前，已有公开入口中可直接进行的技术验证仍是官方后台播放器消费持续媒体。先确定 Android 与 iPhone 都能在真正黑屏时听到锁屏后才生成的新内容，再完成正式业务接入，可避免把尚不成立的传输假设扩展到全业务。

最小实验：

1. 每端各一台真机，断开开发者工具、远程调试和电脑连接；游客前台明确点击开始一次。
2. 真正锁屏关闭屏幕。另一设备分别在锁屏后 1、5、15 分钟随机触发此前未发送的新音频。
3. 游客端全程不解锁、不点击、不重新设置媒体源，实际按序听到新音频才通过。
4. 独立记录业务 JS 心跳与需要 JS 回包的 WSS 随机挑战；不能用服务器发出媒体字节证明手机出声，也不能用解锁后的集中回调证明之前持续执行。
5. 增测数分钟静音、Wi-Fi/蜂窝切换、短断网恢复，以及系统播放器暂停/继续；媒体保持和故障恢复分别记录。

若之后获得锁屏组件接入资格，再比较开启前后是否改变黑屏执行与媒体行为。锁屏卡片的 UI 效果不能作为通过标准。
