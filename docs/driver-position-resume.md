# 跟随车夫：回到现在与重新入房续行

完整浏览、正式选站、近站入队、播放完成与异常恢复动线见[行程与浏览业务动线](./tour-business-flow.md)，其中包含流程图、场景检查表及当前实现边界。

支付宝原生小程序在导航页底部播放器第一行增加“回到现在”，位于房间入口与“跟随车夫”之间。需先加入游客房间并开启跟随，按钮才可使用。此功能读取车夫房间共享的位置，不请求游客手机定位。

## 回到现在

游客查看或播放其他节点时，点击“回到现在”按车夫最新有效经纬度匹配当前站点。匹配沿用站点半径、地点圆形或多边形范围、坐标系转换与路线位置修正，不根据游客正在查看的节点或旧队列推断当前站点。

匹配后切到当前站点，关闭内容与队列面板，恢复地图跟随。显式点击“回到现在”会清空整个旧播放列表、旧断点和临时恢复现场；已完成记录仍由服务端行程保留，但旧的待播、播放中和已跳过队列项不再继续消费。当前匹配节点重新建立为唯一初始待播项并从头播放，后续节点等新的有效位置再次触发后重新入队。清空播放列表不提交“完成”或伪造前序到访，终点前序条件仍需实际到访满足。

房间实时讲解沿用原有播放优先级：实时讲解占用声音时，先切换站点并排入队列，房间暂停或释放声音后再播放该节点，避免同时播放两路声音。当前位置对应已完成节点时允许重听，不重复提交完成。

## 结束后重新加入房间

游客手动结束后，再次加入车夫房间并开始行程，先等待有效车夫位置，再进入匹配站点；不再固定提交起点。已有活动行程中重新加入或恢复房间，也先确认当前位置，避免先播放旧队列或旧断点。

位置过期、精度不足、来自其他房间或账号已变化时不用于续行。当前不在任何可触发站点范围内时提示继续跟随，等待到达站点后开始，不猜测远处节点，也不补播起点。关闭跟随或退出房间会取消等待。

未加入车夫房间或手动关闭跟随时，原手动行程入口仍可从起点开始。

## 登录与扫码核查

- 普通支付宝授权与密码登录成功后，现有实现进入 `/pages/tour/index?view=routes`，展示路线列表，不进入“我的”；本次无需修改。
- APP 邀请码携带字符串 `roomCode` 和 `autoJoin=1`。未完成登录时，房间页将两者传到授权页；登录完成后重新打开原邀请并自动加入，成功后停留在房间。
- 房间码传递依赖当前扫码邀请参数；取消登录不会自动加入，房间已结束时展示服务错误并保留手动重试。

## 验证与发布

`pnpm --filter @path-seeker/mp-alipay test` 包含原生工程构建。新增回归覆盖手动浏览后回到银锭桥、从中途开始新行程、已有行程入房、位置异常、房间音频优先级、房间与账号隔离、已完成节点重听、终点前序条件与关闭跟随；原登录及扫码邀请测试继续验证列表跳转和房间码保留。

`node outputs/driver-position-review/visual-check.cjs` 使用实际播放器 AXML 与 ACSS 转换出的浏览器预览，检查 320px、393px 宽度下八种语言的按钮居中与无横向重叠，并输出布局结果及截图。此检查不代替支付宝真机渲染验收。

构建产物为 `apps/mp-alipay/dist`。发布新版支付宝小程序后，用车夫 APP 持续共享位置，在真机分别验收“手动查看其他点 → 到银锭桥 → 回到现在”和“结束行程 → 中途重新入房 → 开始行程”；同时验证未登录扫码授权后仍进入原房间。本次无需新增后端接口。
