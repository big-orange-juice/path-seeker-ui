# 跟随车夫：整条路线音频预缓存

日期：2026-11-11。

后续更新：[趣事连续播放与锁屏停顿诊断](alipay-tour-audio-continuity-2026-11-12.md) 增加当前与下一段趣事双缓冲、节点首段准备期间继续趣事，以及亮屏恢复前诊断。该后续版本需同步发布 WebAPI 与小程序才能完整采集记录；下文“只发布 WebAPI”仅指本轮预缓存改动。

## 生效范围

游客创建跟随车夫的媒体会话后，后台预取当前路线全部节点的可播放素材。沿用当前导游、语言及跳过附加音频设置，包含讲解章节、启用的前后附加音频及既有队列使用的视频音轨。明确选择的起始节点优先，其余按路线顺序；相同 URL 去重。预取不写到站、已访问或完成进度，不阻塞创建会话和实时播放。

WebAPI 启动时还会后台预热配置中的人文趣事。每个跟随会话的预取也包含匹配路线和语言的趣事。这里的全部节点是当前路线，不是在启动时遍历所有路线、所有导游及所有语言。首次使用的路线仍需准备时间，其他游客可以共享准备结果。

## 缓存与容量

读取顺序为：128 MiB 共享 PCM 内存缓存 → 解码 PCM 磁盘缓存 → 下载源素材并解码。内存淘汰后仍可从磁盘读取，保留磁盘目录时重启可继续复用。

磁盘预算默认 2048 MiB，有效期 1440 分钟，过期及超容量时淘汰旧文件。每秒 PCM 约 32 KB，两小时约 220 MiB，因此只把整条长路线放入原有 128 MiB 内存无法保证后续复用。磁盘缓存仍受容量与有效期限制，不是无限驻留；预算不包括正在写入的临时文件、会话持有音频及 FFmpeg 内存。

缓存文件名使用解析后的完整 HTTPS 地址和 PCM 格式版本的 SHA-256。相对路径先结合 `MediaBaseUrl` 解析。新增音频地址使用新缓存；若在同一 URL 原地更换音频，需等待过期或停服后清理专用缓存并重启。写入使用临时文件再替换，读取失败或目录不可写时回退至原下载路径，并记录警告。缓存素材文件，不缓存游客持续 `media.mp3` 响应。

全局后台预取准备并发为 1，前台播放请求无需排在整个预取队列后；实际解码仍受原有两个解码任务的上限约束。同 URL 的在途任务继续共享。关闭会话取消后续预取，已开始的共享下载允许完成并沿用 90 秒总超时。

## 配置与部署

已在后端 `CulturalTourismSystem.WebApi/appsettings.json` 的 `TourAudio` 增加：

```json
"DiskCache": {
  "Enabled": true,
  "Directory": "App_Data/tour-audio",
  "MaxMegabytes": 2048,
  "Minutes": 1440
},
"Preload": {
  "RouteEnabled": true,
  "IdleOnStartup": true
}
```

`Directory` 相对 WebAPI 程序所在目录解析，也支持独立绝对路径。WebAPI 运行用户需要具有读写权限。发布脚本若删除整个发布目录，请改为持久目录或保留此子目录；容器部署应挂载持久卷。

发布并重启 WebAPI，FFmpeg 继续使用 `/usr/bin/ffmpeg`。本轮不需要数据库迁移、Nginx 改动或小程序重新构建。确认生产环境变量没有覆盖上述配置。重启后游客重新加入房间并开启跟随；重复测试节点时需结束旧行程、开启新行程。

## 检查与现场测试

1. 启动后检查 `Tour audio preload completed startup-idle` 日志，当前 5 段趣事全部成功时为 `ready=5 failed=0 total=5`。
2. 游客开启跟随，检查带会话 ID 的 `Tour audio preload started` 和 `completed`。计数按去重后的素材 URL，不按节点数；当前太阳宫 11 段讲解加 5 段匹配趣事时应为 16。
3. 首次测试等会话 `ready=total failed=0` 后再出发，并确认没有 `Tour audio disk cache write unavailable`。完成日志说明每项曾准备成功，不保证超出预算后仍无限期驻留。
4. 同一路线重新创建会话会复用缓存。保留缓存目录并重启后，`Tour audio prepared` 日志应显示 `source=disk`，对应素材不再下载或解码。`elapsedMs` 为素材准备耗时，不是实际出声延迟。
5. 分别在 Android、iPhone 测试趣事 → 节点 → 趣事续播，出现延迟时复制现有诊断，检查 `stageTimings`、`schedulerStatus` 和 `lagSeconds`。

本轮保持到站范围、停留时间、车夫语音优先及节点顺序播放规则。预取减少下载和解码等待；首次准备未完成或素材失效时仍可能发生静音。后续连续播放更新使到站首段尚未准备好时继续播已有趣事，并提前准备下一段趣事。定位延迟、节点排队及支付宝播放器缓冲需分别排查，不能承诺锁屏零延迟。

## 验证记录

新增用例覆盖全路线预取、导游及语言筛选、附加媒体、去重、起点优先、趣事匹配、启动预热、失败继续、关闭会话取消和关闭配置。磁盘测试覆盖跨编码器实例复用、超过内存容量后从磁盘恢复、过期及损坏文件、容量淘汰、并发写入、目录不可写及 URL 校验。

缓存读取测试故意配置不可用的 FFmpeg 路径和测试域名，确保成功复用时没有隐式重新下载或解码。首轮新增 18 项通过，见后端 `outputs/alipay-formal-validation/tour-audio-preload-focused.trx`。随后补充了真实 FFmpeg 下预取阻塞时到站和音频流仍继续的用例。最终完整媒体回归 **87 项通过、0 失败、1 项跳过**，日志及 TRX 为后端 `outputs/alipay-formal-validation/tour-audio-preload-regression.log` 和 `tour-audio-preload-regression.trx`。跳过项是需单独开启的 15 分钟探针耐久测试，本轮不以本地回归代替真机锁屏验收。
