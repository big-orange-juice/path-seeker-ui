# 博物馆导览解密项目产品方案（融合版）

## 1. 文档定位

| 项目 | 说明 |
| --- | --- |
| 文档名称 | `01-product-solution.md` |
| 当前版本目标 | 融合原始产品方案与后端设计文档 `09-product-solution-vs-implementation-and-flows.md` 的能力视角 |
| 本轮实现范围 | 先补完 C 端内容与 8 类渲染器体验，B 端本轮忽略 |
| 数据策略 | 当前仓库以前端 mock 数据驱动，不依赖 API 已测试或已暴露 |
| 对齐原则 | 文档描述以后端能力上限为方向，以当前前端 mock 落地为第一阶段交付边界 |

## 2. 产品定义

| 维度 | 说明 |
| --- | --- |
| 项目名称 | Path Seeker Museum / 秘径寻踪 |
| 产品目标 | 把传统看展升级为“边探索、边解谜、边获得故事反馈”的导览体验 |
| 产品形态 | B 端管理后台 + C 端微信小程序 |
| 当前代码重心 | 优先把 C 端路线、章节、题型渲染和终局闭环跑通 |
| C 端用户 | 亲子家庭、学生、年轻游客、普通散客 |
| 核心价值 | 提高参与度、停留时长、馆藏内容复用率和活动运营效率 |

## 3. 融合结论

| 维度 | 后端设计结论 | 当前前端落地策略 |
| --- | --- | --- |
| 内容模型 | 后端已经具备内容资产化、路线编排、奖励、Agent 生成与 `route_stage` 骨架 | 前端先不接 API，先用 mock 数据完整承接这些能力的展示结构 |
| C 端主流程 | 已明确有任务列表、详情、剧情开场、地图、章节、终局闭环 | 前端直接按这条完整链路实现，不再停留在 5 章原型 |
| 题型能力 | 后端重点强调 8 类玩法能力与策略扩展性 | 前端统一升级到 8 类渲染器，所有题型先由 mock 数据驱动 |
| 互动表现 | 后端更强在规则和策略，前端薄弱在真实交互表现 | 前端对强调互动的题型补上动画驱动，使用 GSAP 建立反馈层 |
| B 端状态 | 后端已有较完整领域能力 | 本轮不做 B 端，不做后台联调，只保留文档语义对齐 |

## 4. 当前阶段原则

| 原则 | 说明 |
| --- | --- |
| 先跑通体验闭环 | 优先确保用户能从大厅一路玩到终局，而不是先接零散接口 |
| 先 mock，后联调 | 所有页面、题型、奖励、进度先用稳定 mock 数据完成演示与交互验证 |
| 先补互动感 | 对拼图、分支、推理、密码等题型优先加强反馈和动画，而不是只做静态表单 |
| 页面服务于线下看展 | 手机界面必须把用户拉回展品和空间，而不是把注意力锁死在屏幕 |
| 文档和代码同步 | `product-solution` 中写到的 8 类玩法与体验节奏，必须在当前前端 mock 中能看到对应实体 |

## 5. C 端核心体验结构

### 5.1 主流程总览

| 阶段 | 页面 / 节点 | 用户目标 | 系统输出 |
| --- | --- | --- | --- |
| 1 | 任务大厅 | 找到适合自己的路线 | 年龄、难度、玩法筛选，主题路线卡 |
| 2 | 任务详情 | 判断要不要开始 | 剧情简介、路线长度、奖励、年龄档确认 |
| 3 | 开场剧情 | 进入任务状态 | 角色引导、行动手册、第一站目标 |
| 4 | 章节地图 | 知道当前该去哪里 | 当前章节、路线进度、线索袋、下一步入口 |
| 5 | 展品观察页 | 先看展品，再理解问题 | 观察点、故事片段、可疑细节、检查清单 |
| 6 | 谜题页 | 完成一次短时高反馈交互 | 8 类题型渲染、提示、错误反馈、奖励反馈 |
| 7 | 章节过场 | 感受到推进与收获 | 新线索、碎片、完美推进状态、下一站提示 |
| 8 | 终局结算 | 获得完整闭环 | 真相揭示、成绩卡、知识回收、分享文案 |

### 5.2 当前前端页职责

| 页面 | 主要职责 | 当前实现要求 |
| --- | --- | --- |
| `pages/shell/index` | 任务大厅 + 继续游玩 + 已完成归档入口 | 支持年龄、难度、玩法筛选，展示路线卡 |
| `pages/task-detail/index` | 任务详情与开始前确认 | 展示 8 章路线预览，并允许选择年龄档 |
| `pages/prologue/index` | 开场剧情 | 展示人物引导、剧情 beat、行动手册 |
| `pages/chapter-map/index` | 全流程导航枢纽 | 展示章节状态、线索袋、当前任务 |
| `pages/artifact-clue/index` | 观察与线索页 | 强调“先观察后作答” |
| `pages/puzzle/index` | 题型渲染与交互 | 统一承接 8 个 renderer |
| `pages/chapter-result/index` | 章节收束 | 奖励反馈、完美推进、下一步提示 |
| `pages/finale/index` | 终局页 | 真相、成绩、知识回收、可分享文案 |

## 6. 路线节奏规则

| 路线阶段 | 建议难度 | 推荐题型 | 目标 |
| --- | --- | --- | --- |
| 开场 1-2 题 | L1 | `observe_choice`、`clue_find` | 快速进入状态，建立观察习惯 |
| 中段推进 | L2 | `sort`、`match`、`image_puzzle` | 形成章节节奏和线索拼装感 |
| 叙事转折 | L2 | `story_branch` | 让玩家判断哪条解释更接近真相 |
| 闭环前夜 | L3 | `multi_step_reasoning` | 把前文证据收束成一条有效链 |
| 终局高峰 | L3 | `code_break` | 用前面所有章节回收结果完成最终解锁 |

## 7. 8 类固定渲染器

### 7.1 渲染器总表

| templateType | 中文名 | 交互形式 | 推荐难度 | 动画要求 | 当前状态 |
| --- | --- | --- | --- | --- | --- |
| `observe_choice` | 观察选择 | 观察后单选 | L1-L2 | 选项分批入场，选中回弹 | 本轮实现 |
| `clue_find` | 细节找线索 | 点选热点 | L1-L2 | 热点显隐、命中弹跳 | 本轮实现 |
| `sort` | 顺序排序 | 上下调整顺序 | L2 | 列表重排反馈 | 本轮实现 |
| `match` | 线索配对 | 左右配对 | L2 | 匹配成功闪动与回弹 | 本轮实现 |
| `image_puzzle` | 图像拼图 / 碎片重构 | 调整碎片顺序 | L2 | 拼图片段入场、换位动画 | 本轮实现 |
| `story_branch` | 剧情判断 | 选择分支说法 | L2 | 卡片入场、选中展开 | 本轮实现 |
| `multi_step_reasoning` | 多步推理 | 选证据 + 下结论 | L3 | 证据链逐步成形、结论激活反馈 | 本轮实现 |
| `code_break` | 密码解锁 | 输入终局密码 | L2-L3 | 槽位回弹、片段入场 | 本轮实现 |

### 7.2 与后端玩法骨架的映射

| 后端语义 | 前端 renderer | 说明 |
| --- | --- | --- |
| 观察选择题 | `observe_choice` | 直接映射为观察后单选 |
| 细节找线索 | `clue_find` | 通过热点区域完成判定 |
| 顺序排序 | `sort` | 通过顺序调整完成判定 |
| 线索配对 | `match` | 通过左右关系映射完成判定 |
| 图像拼图 | `image_puzzle` | mock 阶段先用“碎片顺序拼回”承接交互，后续可升级真实切片 |
| 剧情判断 | `story_branch` | 分支卡片负责承接叙事选择 |
| 多步推理 | `multi_step_reasoning` | 先选证据再选结论，形成两段式判断 |
| 密码解锁 | `code_break` | 终局或章节高峰题 |

### 7.3 动画驱动原则

| 题型 | 动画目标 | GSAP 使用方式 |
| --- | --- | --- |
| `observe_choice` | 建立入场节奏与点击确认感 | 选项 stagger 入场，选中回弹 |
| `clue_find` | 让热点可感知，不做死板点选 | 热点逐个浮现，命中后放大与高亮 |
| `sort` | 让重排行为有“移动”感 | 操作后整组列表短时位移再归位 |
| `match` | 让配对成功像“连上线”而不是简单存值 | 配对卡片批量回弹与高亮 |
| `image_puzzle` | 让拼回碎片有逐步成像感 | 槽位先入场，碎片换位后整体回弹 |
| `story_branch` | 把选择做成剧情节点，不是普通 radio | 卡片左移入场，选中后展开结果段 |
| `multi_step_reasoning` | 强化证据链被一步步构建的过程 | 证据卡入场、推理链 chip 成形、结论激活 |
| `code_break` | 强化终局紧张感与完成感 | 片段先浮现，密码槽输入后逐槽回弹 |

## 8. 年龄档与难度模型

### 8.1 年龄档

| 年龄档 | 理解方式 | 文案要求 | 当前是否支持 |
| --- | --- | --- | --- |
| `6-10` | 以观察、简单因果、直接任务为主 | 短句、直接、鼓励感强 | 是 |
| `10-15` | 能接受关联判断和轻推理 | 有任务感和一点悬念 | 是 |
| `15+` | 能接受多线索推理和更高知识密度 | 更克制，允许信息量更高 | 是 |

### 8.2 难度档

| 难度档 | 目标体验 | 线索结构 | 适配题型 |
| --- | --- | --- | --- |
| `L1` | 快速上手 | 1 个明显线索 | 观察选择、找线索 |
| `L2` | 有挑战但不劝退 | 2-3 条线索关联 | 排序、配对、拼图、分支判断 |
| `L3` | 明显成就感 | 多线索交叉验证 | 多步推理、终局密码 |

## 9. 当前 mock 实现边界

| 模块 | 当前做法 | 暂不处理 |
| --- | --- | --- |
| 路线数据 | 使用 `apps/mp-wechat/src/mock/missions.ts` 生成 3 条完整 8 章路线 | 不接后端已发布路线接口 |
| 进度存储 | 使用本地 store + storage 恢复进度 | 不做跨设备同步 |
| 判题 | 在前端 store 内按 payload 直接判定 | 不走后端评分、排行榜、徽章发放接口 |
| 奖励反馈 | 用 mock 线索、碎片、成绩卡、分享文案驱动 | 不生成真实海报、不接真实 badge / collection 数据 |
| 分支 / 推理 | 先在 mock 路线内完成结构验证 | 不对接真实 `route_stage` / `NextStageId` |

## 10. 本轮代码交付要求

| 类别 | 要求 |
| --- | --- |
| C 端页面 | 必须形成大厅 -> 详情 -> 开场 -> 地图 -> 观察 -> 解谜 -> 章节结果 -> 终局的完整可试玩闭环 |
| 题型覆盖 | 必须覆盖后端强调的 8 类渲染器 |
| 动效要求 | 对 `image_puzzle`、`story_branch`、`multi_step_reasoning` 等强交互题型必须有动画驱动 |
| 技术手段 | 当前项目已安装 `gsap`，动画优先用 GSAP 实现 |
| API 策略 | 不等待接口测试与暴露，先用 mock 数据验证产品节奏与交互形式 |
| B 端 | 本轮不做，不扩展后台，不做后台联调 |

## 12. 结论

| 项目 | 结论 |
| --- | --- |
| 当前产品本质 | 内容运营平台支撑下的线下实景轻游戏 |
| 当前实现重心 | 先把 C 端内容补完，尤其是 8 类玩法渲染与章节推进节奏 |
| 当前工程策略 | 先 mock、先动效、先体验闭环，再接真实 API |
| 与后端关系 | 以后端能力设计为方向，但本轮前端先把表现层和交互层补齐 |
