# C 端长按语音输入与景点内容联动

## 交互

- 行程地图上的麦克风、外壳悬浮菜单中的“问”支持按住说话。
- 按下时立即暂停讲解／中止当前问答，并在同一次用户手势中启动收音，避免移动浏览器拒绝定时器里的开麦操作，也避免漏掉开头的话。首次按下可能触发麦克风授权，聊天面板保持关闭，实时显示识别文字。
- 外部按钮松开时立即进入 `/shell/ask` 全屏问答页，不等待识别完成，也不以按住时长作为跳转门槛。问答 store 接管剩余识别过程，页面显示“正在识别”，结果返回后自动发送；来源页面卸载不会取消本次输入。
- 外部按钮短按同样进入全屏问答页；Chat 内部麦克风短按丢弃本次收音。向上移动至少 60 像素后松开取消。取消、无内容、权限失败或切后台不会发送问题。授权弹窗引起的窗口失焦不取消收音。外部按钮发生识别失败后，松开仍进入问答页并显示失败原因。
- 长按会暂停路线讲解并保存断点；取消后尝试恢复。成功提问后沿用问答结束恢复讲解的机制。
- Chat 内部麦克风共用长按控制器，取消不会发送。

## 识别边界

使用 Web Speech API，启用持续识别。浏览器在停顿后结束识别时，按住期间会重新启动并保留已识别文本。松开后的最终结果等待有两秒收尾上限；仍没有结束回调时使用已获得的文本。浏览器兼容性、麦克风权限和厂商识别服务仍影响实际体验；不支持语音的浏览器可短按进入文字问答。

浏览器意外返回 `aborted` 时，按住期间最多连续重试两次并保留已有文本；主动松开后的 `aborted` 视为正常收尾。启动回调未到达时松开，会等待启动后再停止；超时会主动释放识别引擎。权限、网络、设备与未知错误分别提示原因。当前正式后端仍没有音频上传识别接口，这些修复不消除对浏览器厂商识别服务的依赖。

开始语音输入会释放问答播放期间用于说话打断的麦克风流，防止两个收音器同时占用设备。此前尚未完成的麦克风授权／初始化也会失效，迟到的流立即释放。成功提问后，问答播放按原有授权规则重新启用说话打断。

## 景点内容

新景点播放队列开始时，右侧内容面板默认自动打开并切换到当前播放景点，包括首站、手动切站、上一／下一节点浏览和顺序自动推进。切换景点时重新挂载内容组件，使阅读位置回到顶部。开启“锁定当前内容”后，自动播放不再切换正在阅读的内容，手动选择仍可切换。附近景点的统一入队、去重和播放控制详见 [C 端游览控制与播放序列](69-c-client-tour-controls.md)。
