# APP 本地二维码邀请

Android 0.3.2 在「游客扫码」弹窗中使用 ZXing 本地生成 720×720 的普通二维码。创建和校验房间仍使用现有 `TranslationRooms` 接口，二维码生成不调用后端或支付宝网关。

码内容使用 `https://ds.alipay.com/?scheme=` 包装 `alipays://platformapi/startapp`，指定小程序 AppID、`pages/translation-room/index` 页面和 `roomCode=八位房间码&autoJoin=1`。query 参数与外层 scheme 分别编码，房间码始终保留字符串。默认 AppID 为 `2021007110628321`，可通过 Android `local.properties` 的 `alipay.appId` 在构建时覆盖。

小程序直接进入房间页面后，等待身份及权限确认完成再自动加入，使用当前保存的收听语言，成功后停留在房间。未完成授权的游客在登录后返回原邀请，继续自动加入。正常手动输入入口仍需要点击加入；小程序内扫一扫也能解析此邀请链接及原有房间链接、八位纯房间码。后台收到新的扫码入口时打开对应房间，已有相同房间连接则恢复连接。

自动加入失败后展示原服务错误，保留手动重试，不循环请求。账号切换、页面隐藏或失效参数不能使迟到的加入响应接管当前连接。房间有效期及车夫身份判断仍由现有后端执行，二维码自身不会延长房间有效期。

## 发布和验证

1. 发布包含本次自动加入逻辑的支付宝小程序；普通启动链接打开该 AppID 可访问的版本，无法代替开发预览或体验码。
2. 安装 Android 0.3.2；创建房间，确认即使后端没有 `qrImageDataUri` 也能展示二维码。
3. 用另一台手机的支付宝扫一扫，分别核对冷启动、热启动、首次授权、已有另一房间及非中文语言偏好。
4. 关闭房间后扫旧码应提示失效，新建房间后的码应加入新房间。车夫用自己的账号扫码不能从小程序接管 APP 房主连接。

构建和单元测试验证二维码可解码、参数编码和自动加入逻辑；支付宝是否直接识别启动链接、目标版本是否已发布，以及实际收听仍需真机联调确认。本次不需要部署新后端，不需要配置支付宝私钥或调用小程序码生成 API。
