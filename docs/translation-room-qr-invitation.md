# APP 本地二维码邀请

Android 0.3.4 在「游客扫码」弹窗中使用 ZXing 本地生成 720×720 的普通二维码。创建和校验房间仍使用现有 `TranslationRooms` 接口，二维码生成不调用后端或支付宝网关。

码内容使用 `https://ds.alipay.com/?scheme=` 包装 `alipays://platformapi/startapp`，指定小程序 AppID、`pages/translation-room/index` 页面和 `roomCode=八位房间码&autoJoin=1&routeCode=OUT-610000000000000001-20261030102158`。query 参数与外层 scheme 分别编码，房间码始终保留字符串。默认 AppID 为 `2021007110628321`，可通过 Android `local.properties` 的 `alipay.appId` 在构建时覆盖。当前版本固定为该 A 线路线代码，APP 内手动选路线留待后续版本。

扫码未登录或只有游客身份时，直接进入支付宝手机号授权登录页，不先请求游客登录。用户同意隐私说明并主动点击授权按钮后，登录成功返回原邀请并自动加入；取消或拒绝授权不自动以游客身份入房。已完成正式登录的用户跳过授权。扫码入口的授权页不提供游客登录选项。

加入房间使用本机保存的收听语言，未选择语言时默认中文。成功后保持房间会话，打开路线列表/概览，并定位到二维码路线代码对应的当前语言版本。`routeCode` 对应客户端目录的 `familyCode`，以完整值精确匹配；不使用包含匹配，避免进入其他路线。各语言路线的主键可以不同，但须拥有相同的路线族代码。目标语言路线未发布或代码不存在时显示路线不可用，不自动跳到无关路线。二维码也支持可选的 `lang=zh|en|ru|es|fr|ja|ko|yue` 来固定语言，或通过字符串 `routeId` 指定单个语言版本；本版 APP 不写入 `lang`，保留游客的选择。

正常手动输入入口仍需要点击加入；小程序内扫一扫也能解析此邀请链接及原有房间链接、八位纯房间码，并保留路线及语言参数。旧二维码缺少路线参数时，入房后打开当前语言的路线列表。后台收到新的扫码入口时打开对应邀请，同一房间的新路线或语言参数也会被处理。

启动链接的 `query` 可能只出现在应用的 `onLaunch/onShow` 参数中，而房间页的 `onLoad` 参数为空。冷启动时应用先暂存包含房间、路线和语言的有效邀请，房间页在缺少页面房间码时读取并立即清除该邀请，再继续授权和自动加入流程；显式页面房间码优先。不能只验证向页面直接传参的场景，否则会漏掉“能打开房间页，但房间码为空”的实际扫码问题。此修复需重新发布支付宝小程序；二维码携带固定路线需要更新到 Android 0.3.4。

自动加入失败后展示原服务错误，保留手动重试，不循环请求。账号切换、页面隐藏或失效参数不能使迟到的加入响应接管当前连接。房间有效期及车夫身份判断仍由现有后端执行，二维码自身不会延长房间有效期。

## 发布和验证

1. 发布包含本次自动加入逻辑的支付宝小程序；普通启动链接打开该 AppID 可访问的版本，无法代替开发预览或体验码。
2. 安装 Android 0.3.4；创建房间，确认即使后端没有 `qrImageDataUri` 也能展示二维码，并携带固定 A 线路线代码。
3. 用另一台手机的支付宝扫一扫，分别核对冷启动、热启动、首次授权、拒绝授权、已有另一房间、未选语言及非中文语言偏好；确认授权后自动入房，继而进入对应语言的 A 线路线概览，并保持房间收听。未选语言应进入中文，不再停在语言选择页。
4. 关闭房间后扫旧码应提示失效，新建房间后的码应加入新房间。车夫用自己的账号扫码不能从小程序接管 APP 房主连接。

构建和单元测试验证二维码可解码、参数编码和自动加入逻辑；支付宝是否直接识别启动链接、目标版本是否已发布，以及实际收听仍需真机联调确认。本次不需要部署新后端，不需要配置支付宝私钥或调用小程序码生成 API。
