# 实时讲解游客反向提问实施记录

日期：2026-11-01。覆盖后端、H5 与支付宝原生小程序。代码已实现；生产部署、真实供应商链路与手机端交叉联调尚未执行。

## 用户行为

- 游客在房间内按住“对车夫说话”，松开发送，可以取消。最长 30 秒，短于 0.3 秒拒绝上传。H5 支持键盘空格或回车按住录音。
- ASR 语言提示使用游客当前收听语言，目标语言始终取房间的讲话语言，不能由提交者指定其他接收人。
- 原文与译文仅发给车夫和当前发言游客，译音仅发给车夫。其他游客不接收该提问。
- 车夫初次点击“收听提问”开启该会话的提问声音。若正在讲解，显示“暂停讲解并收听”，先停止麦克风、排空尾包并等待服务器确认，再播放。
- 开启提问收听后，后续已完成的提问按房间接受顺序播放。停止播放、恢复讲解或其他内容抢占声音后，需要再次点击收听。
- 车夫讲解的恢复由用户手动触发，不自动开麦。主动暂停时保持房间连接，不触发原有离线一分钟超时；实际离线仍受清理规则约束。
- 游客录音期间暂停本机译音；麦克风实际停止后恢复后续完整讲解段，不补播录音期间的旧段。
- 断线、退出、切账号和关闭房间会清理待播放音频；重连不补发历史提问音频。文字只在当前前端会话中保留。
- 录音、提问状态、错误及播放按钮支持现有八种房间语言。

## 后端接口与状态

`POST /api/TranslationRooms/{roomId}/questions`，使用现有游客端认证。请求是 multipart/form-data：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `requestId` | string | 32 位十六进制 GUID，同用户、同房间内用于重复请求去重 |
| `file` | WAV | PCM、16 kHz、单声道、16 bit、0.3～30 秒，最多 1000000 字节 |

返回 `questionId`（字符串）和当前状态。HTTP 接收完成后，由房间内有界后台任务处理 ASR、翻译和 TTS，不持有 HTTP 请求作用域。识别及翻译服务复用现有 MiniMax 和房间翻译服务。

结果经现有 `/events` 连接发送 `question.updated`，载荷包含：`id`、`speakerId`、`displayName`、`sourceLanguage`、`targetLanguage`、`source`、`text`、`status`、`error`、`expiresAt` 和 `audio`。`id` 与 `speakerId` 均为字符串，`expiresAt` 为 Unix 毫秒数。

状态依次为 `accepted` → `recognizing` → `translating` → `ready`；TTS 缺失时为 `text_only`，识别或翻译失败为 `failed`，取消或超时为 `expired`。`playing` 和 `played` 是客户端本地状态，不视为服务器播放回执。

服务器只在原房主和原发言游客连接上发送结果；重连后的替代连接不会收到旧任务的音频。发言游客收到的 `audio` 固定为 null。车夫收到完整音频句子的 `{ hex, format }` 数组。提问事件没有讲解段落的目标语言订阅语义，两端独立处理，不混入车夫讲解段号或语言游标。

新增 `input.pause`，可从 H5 的 `/input` 和支付宝共享的 `/events` 输入轮次发送。服务器处理尾包并结束该输入轮次后，在房主事件连接发送 `input.paused`；房间保持可继续讲解。原 `input.end` 仍表示结束讲解。

默认限制：同房间最多 4 条待处理提问，两分钟内最多保留 30 条请求去重记录，同游客两次接受间隔至少 5 秒；提问从接受起两分钟有效。TTS hex 总量最多 4 MiB。客户端最多保留 20 条提问，音频不会进入 Vue 页面 props 的消息数据或支付宝 `setData`。

## 配置和发布

后端开关 `TranslationRoom:GuestSpeech:Enabled`，默认 true；设置环境变量 `TranslationRoom__GuestSpeech__Enabled=false` 可拒绝新提问。房间快照通过 `guestSpeechEnabled` 通知前端，前端在不支持该能力的后端上隐藏入口。已创建的房间在读取、重连或创建／返回房间时刷新能力。

按后端 → H5 → 支付宝顺序发布。无需新增数据库表或字段，也无需新增语音供应商。现有房间翻译会话仍会通过原服务写入聊天会话记录，首版不额外建立可查询的提问历史或离线补收功能。
