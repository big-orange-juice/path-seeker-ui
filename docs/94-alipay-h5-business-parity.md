# 支付宝小程序 H5 业务补齐与实机验收

本次范围是此前差异中的第 1、2、3、4、6、7 项。第 5 项按产品前提“已上架路线一定有讲解音频”排除，不增加浏览器 TTS 替代服务。先验证现有 HTTP/SSE 和支付宝原生能力，再根据实机结果评估 WebSocket 等方案。

本次修改位于 `apps/mp-alipay`，复用现有后端接口。`dist` 已由源码构建，可在支付宝开发者工具导入 `apps/mp-alipay`；工程代码目录指向 `dist`。本地构建、静态模板校验和模拟测试不能代替支付宝原生编译与手机联调。

## 六项实现

| 原差异 | 当前实现 | 平台限制或验收重点 |
| --- | --- | --- |
| 1. 增量回答与音频 | 探测请求分块回调；跨字节解码 UTF-8、增量解析 SSE；文字到达即更新，每句音频收齐即写临时文件并加入播放队列；队列可等待下一句，完整响应不重复播放 | 若客户端不提供分块或网关缓冲，则等完整响应后处理；未引入 WebSocket。按句文件播放仍可能存在切句间隙，需听感验收 |
| 2. 导览点击提问 | 点击暂停讲解、立即开始收音并打开问答弹层；内容页再次点击结束并转写，成功后自动发送一次，保留路线/站点/章节上下文 | 使用原生 WAV 转写，需要支付宝 10.6.36+；首次授权、录音交接、拒绝权限需要真机检查 |
| 3. 问答完整交互 | 开关式录音；原生启动成功后显示连续波浪收音动效；字幕跟随当前音频句；Markdown、失败重试；页内浮层与展开共用实例；朗读时点击麦克风取消旧回答并录音 | 波浪为收音状态动效，不表示实际音量。另有默认关闭的“说话打断”，探测实时录音帧 API 后提供开关。本机 PCM 能量检测不做识别，不上传帧；录放并行、帧格式和回声效果待实测 |
| 4. 选站与浏览语义 | 正式行程中地图/列表选站发送开始事件并播放；上一站/下一站只浏览并播放，不写进度、不自动完成；已完成站重听不重复记账 | 未开始行程仍可浏览，需显式开始行程；保留原来的自动/手动完成来源规则 |
| 6. 地图与恢复 | 跟随定位、路线显隐、缩放、地图全屏；隐藏路线保留范围边界；前台恢复按离开前的播放意图；问答结束/关闭恢复被打断音频，包括单独额外音频 | 定位跟随使用 GCJ-02，范围判定仍用 WGS84；弱定位不驱动地图。原生 direction 可用时更新朝向。主动暂停、切换账号/站点不会误恢复 |
| 7. 历史返回路线 | 本机漫游、进行中、已完成、足迹均提供返回路线操作，保持字符串路线 ID，记录有有效语言时同步选择 | 未发布或缺失路线仍由目录错误/空态反馈。没有新增跨设备户外历史接口 |

## 实机操作清单

建议在同一条已上架且音频齐全的路线，对照 H5 完成下表。记录机型、系统、支付宝版本、工具版本和网络环境。所有“待测”均不代表已在设备通过。

| 场景 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- |
| 原生编译 | 导入并编译工程，打开漫游、独立问答及浮层 | 无模板、组件或模块错误，浮层完整显示且可输入 | 待测 |
| 文字流式 | 发送需要较长回答的问题 | 有分块时，回答未结束便持续出现文字；否则完整答案仍正确显示 | 待测 |
| 首句音频 | 同一问题开启语音回复 | 有分块时，首句音频收齐即可播放，早于整轮结束；不因完整响应再播放一次 | 待测 |
| 接句与字幕 | 听完整多句回答，观察句字幕、进度 | 音频按句有序、字幕跟随当前句；记录首句等待和切句间隙是否可接受 | 待测 |
| 浮层 | 导览播放中打开问答，提问后多次展开/收起，再关闭 | 展开/收起不取消回答，地图不覆盖面板；音频结束/关闭后按原位置恢复讲解 | 待测 |
| 导览语音 | 点击导航麦克风，至少说 1 秒后再次点击内容页麦克风 | 立即打开问答并持续收音；波浪仅在原生启动成功后出现，停止后识别并自动发送一次 | 待测 |
| 取消与权限 | 启动期间再次点击、关闭问答、切文字模式、切后台、拒绝麦克风 | 取消不提交问题，迟到回调不发送；权限失败有反馈，可继续文字问答 | 待测 |
| 收音与展开 | 收音期间多次展开、收起弹层；另录满60秒 | 展开收起不中断；60秒原生停止后自动识别发送 | 待测 |
| 点击打断 | 回答朗读中点击麦克风，提出新问题 | 旧回答停止，新录音成功；旧回调不会停止新音频 | 待测 |
| 自动人声打断 | 有开关时开启，分别用耳机和外放听回答并开口 | 开口可停止朗读，安静时不误触发；失败可关闭并点击麦克风。记录是否支持实时帧、是否误把外放识别为人声 | 待测 |
| 富文本与重试 | 提问获取标题、列表、代码或表格；断网后重试 | 正文格式正确，无原始 HTML 执行；重试发送原问题 | 待测 |
| 选站 | 开始行程，分别点地图标记和站点列表 | 正式进入所选站并播放，对应开始事件及行程位置正确 | 待测 |
| 浏览 | 正式行程中使用上一站/下一站并听到结束 | 仅浏览播放；不改服务端当前站，不提交完成，不自动续站 | 待测 |
| 前后台 | 播放中切后台再返回；主动暂停后再做一遍 | 播放中离开可恢复；主动暂停不自动开播；切账号/站点不恢复旧内容 | 待测 |
| 额外音频 | 单独播放额外音频，提问后返回 | 恢复同一段和位置，不误提交本站完成，不覆盖主讲解断点 | 待测 |
| 地图 | 户外启用定位、跟随、缩放、显隐路线、地图全屏 | 跟随实际位置；目的地和景点范围仍显示，控制可用 | 待测 |
| 历史 | 在四个记录分类中返回路线 | 打开记录对应的路线，ID 和语言未丢失；不可用路线有提示 | 待测 |

## 传输与人声检测的判定依据

分块接收依赖支付宝运行时实际返回的任务是否有 `onChunkReceived`，以及服务器/代理是否及时发送数据。能力探测仅用于兼容，不证明所有支付宝版本支持该 API。可在调试器记录首个分块、首个文字、首句音频和整轮完成时间，避免将服务器生成慢或代理缓冲直接归因为播放器。模拟环境已覆盖分块路径和完整响应回退路径。

人声检测使用 16 kHz、单声道 PCM 的能量阈值与持续时长判断，和手动语音识别共享录音设备所有权；手动录音会等待检测收音结束。原生 API 即使有帧回调，也仍需确认 PCM 参数、回调数据、播放与录音能否并行。检测不上传音频帧，原生接口生成的临时文件在停止后清理。当前能量检测不包含回声消除保证，外放效果应独立记录。

实机确认 HTTP 分块不可用、代理无法及时透传，或句文件接续体验无法满足要求后，再据此决定是否新增服务端传输/播放方案。本次保留了文字问答、完整响应音频和手动点击收音的可用路径。

## 自动验证

执行 `pnpm test:mp-alipay` 会先构建工程再运行测试。新增回归位于 `apps/mp-alipay/tests/h5-parity.test.cjs` 和 `barge-in.test.cjs`，覆盖分块中文字节、按句提前播放、回退与去重、取消竞争、异常响应停止音频、录音交接和自动提交、浮层生命周期、历史加载失败不自动提问、站点进度隔离、地图、播放恢复、人声检测和录音所有权。
