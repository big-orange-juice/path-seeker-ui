# 持续讲解竞态审计与复测

## 已复现的风险与修复

这轮检查覆盖媒体会话创建、控制队列、原生播放器重连、选站与额外内容、房间切换/关闭/换语言、播放进度确认，以及服务端房间事件和异步语音解码。

| 触发条件 | 原来可能发生什么 | 本轮修复 |
| --- | --- | --- |
| 恢复请求尚未返回，又点击暂停 | 旧恢复响应重新调用原生播放 | 记录最新播放意图，旧响应不能启动播放器 |
| 重连途中打开问答 | 重连完成抢回问答的音频所有权 | 重连完成同时验证会话、意图和挂起状态 |
| 创建会话途中暂停、提问或改自动播放设置 | 控制被丢弃；创建成功后错误自动播放 | 控制归属于正在创建的会话，成功后按序执行；本地暂停意图立即生效 |
| 切换房间/导游时两次创建重叠 | 旧请求晚创建，替换新媒体订阅 | 同一客户端串行提交创建；过期结果撤销；等待期间再次切换会取消中间创建 |
| 旧选站响应或异步播放续接在切房间后返回 | 给新会话发旧节点、恢复等命令 | 异步操作绑定会话 ID；换账号、路线、导游或语言后失效 |
| 切房、立即关房或选择语言时执行清理回调 | 旧房间短暂仍可用，重新创建旧媒体会话 | 先更新房间状态，再触发清理和订阅通知 |
| 重连前发出的轮询在新播放器启动后返回 | 把新播放器时钟用于旧 streamId 的完成确认 | 校验轮询请求时的播放器代次、当前代次及服务端 streamId；重连期间不确认 |
| 补充音频等待挂起响应时打开问答/离页 | 迟到的补充音频抢占新内容 | 校验具体播放请求与页面上下文；废弃回调不启动播放 |
| 补充音频报错，同时触发完成 | 重复释放、重复重连 | 每次补充内容只释放一次；已挂起时不重复发送中断挂起 |
| 补充音频/视频播放中进入后台 | 内部播放器停止回调，路线长期挂起 | 离页时释放补充内容占用，恢复原生持续流，不等内部播放器结束 |
| 会话创建状态通知同步重入 start | 同一创建返回尚未初始化的 Promise | 先建立创建 Promise，再通知订阅者 |
| 司机新一轮已开始，旧轮次 drained 事件到达 | 误认为司机已结束，路线音频插入 | 前后端匹配讲话轮次；优先使用事件 payload 的原始 epochId |
| 房间语音解码过程中挂起再恢复 | 已应丢弃的旧语音晚解码成功，又入队 | 暂停、挂起、静音、重连使旧解码代次失效，完成时核对代次 |

所有业务 ID 和讲话轮次 ID 保持字符串。控制意图版本只用于当前进程中的并发判断。

## 原地压力复测

Android 和 iPhone 分别执行。先确保普通节点、入房节点均实际出声，司机暂停实时讲话后测试路线音频。

- 连续操作“暂停 → 恢复 → 暂停”，最后一次暂停应保持；再点恢复，应出声。
- 恢复后马上打开问答，问答不能被路线抢音；关闭后路线恢复。
- 入房/创建媒体期间立刻关闭跟随、打开问答，再返回；设置应保留。
- 快速换节点、换房间、换语言，旧声音和旧错误提示不能覆盖新会话。
- 播放补充音频时立即提问；播放补充内容时离页，再返回；路线不能永久挂起。
- 司机连续暂停和重新开始讲话，旧轮次结束不得让路线讲解插入新一轮讲话。
- 退出房间后手动播放普通节点，重新加入后再验证 A 播放中锁屏、A 结束后到 B/C 自动出声。

如有失败，先复制页面诊断记录，保存最后操作顺序和发生时间，再重试。记录是否只是震动、是否实际出声、是否保持锁屏；不要只用媒体卡片或时间前进判定成功。
