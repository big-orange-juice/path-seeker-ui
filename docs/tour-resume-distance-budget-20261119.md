# 跟随车夫重连续播预算

后端实现于 `CulturalTourismSystem.Service/Chat/TourAudioSessionService.Resume.cs` 和 `TourPlaybackResumePlanner.cs`。配套现有支付宝小程序的创建、重连、手动 realign 指令生效，不要求增加客户端请求字段。

## 行为

- 关闭后重进、网络重连和手动重新连接，恢复有效的实际收听断点后，先保持旧节点讲解静音并测算预算。
- 条件为：当前节点全部剩余音频时长 + 安全余量 <= 到下一有效节点触发范围入口的预计时间。
- 可以播完则从原片段偏移继续；无法播完则跳过该旧节点的自动续播，静音等待后续有效到站。
- 剩余时长包括当前片段、后续章节、配置启用的前后额外音频及节点视频音轨。优先用媒体时长，缺失时通过解码取得真实时长；无法获取时不假定为零。
- 有可靠单条路线几何时，沿前进方向寻找触发范围入口；已越过范围则预算为零。路线重合、投影歧义、缺失几何等场景回退到保守的直线范围距离。圆形半径、多边形和接近距离均参与计算，另扣除定位精度余量。
- 用最近有效定位估计行驶速度，过滤重复、过期、精度差和异常跳点。近期速度取较高分位并增加 25% 余量；停车或数据不足使用参考速度，避免零速度产生无限预算。
- 时长获取和定位等待各有最长约 8 秒限制。仍无法判断时静音等待，不反复启停旧讲解。
- 本次会话一旦进入静音等待，后续重连/realign 不会再自动恢复旧断点。下一有效到站会解除等待，多个同时到站只选择本批路线顺序靠后的有效节点，其余不继续积压。
- 测算允许续播后，如果新节点提前实际触发，取消旧媒体连接，让客户端现有恢复流程清除旧缓存并连接新节点；避免手机继续播放已经发送的旧内容。
- 静音等待期间以及新节点音频加载期间不插入沿途趣事。车夫实时语音仍保持原有优先级。
- 末站没有下一节点时允许续播；播完仍使用既有自动关闭跟随、退出游客房间的逻辑。

## 默认参数

| 后端配置 | 默认值 | 用途 |
| --- | --- | --- |
| `TourAudio:Resume:ReferenceSpeedMetersPerSecond` | 3 米/秒 | 无可靠移动速度或停车时的参考车速；允许 1.5–12 米/秒 |
| `TourAudio:Resume:SafetySeconds` | 10 秒 | 续播预算中的额外时间余量；允许 0–60 秒 |

无需新增数据库字段。状态接口新增可选 `resume` 诊断字段，记录状态、原因、下一节点 ID、剩余秒数、入口距离、测算速度、预计到达秒数及距离来源。后端 `Tour resume budget` 日志记录最终决策。

## 验证场景

- 相同距离、不同车速以及不同剩余音频长度，决策应不同。
- 停车、重复定位、过期定位、跳点、圆形/多边形范围、路线弯道、重合路线投影和已经过站。
- 长讲解保持静音，随后触发新节点；等待及新节点加载时没有旧讲解或沿途趣事。
- 多章节按全量剩余时长判断，短剩余从实际断点续播。
- 下一节点提前触发时旧流断开，新流直接播放新节点。
- 手动 realign 与普通重连均测算，静音等待在同一会话内反复重连仍保持。
- 定位超时或媒体时长不可取得时静音兜底；末站正常结束。

自动化测试使用模拟定位及真实 FFmpeg 流；实际车速分布、定位误差及支付宝设备缓冲清理仍需实车校准。无可靠路线几何时，直线距离不能证明车辆已经跨过某一节点，采用较保守的预算并以真实到站作为切换依据。
