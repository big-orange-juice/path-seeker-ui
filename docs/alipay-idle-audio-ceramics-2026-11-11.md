总解码时长为 1096.189 秒，约 18 分 16 秒。已设置 `Enabled=true`，每项 `Language=zh`，不设置 `RouteId`，作为所有中文路线跟随会话的通用空闲节目，包含当前黄包车行程。这里的来源路线 ID 只记录素材出处；如果把它写入每项 `RouteId`，会将播放限制在陶瓷路线，无法用于黄包车路线。

节目按配置顺序循环。车夫房间语音和已触发节点讲解优先；空闲节目让出播放后保留进度，恢复时续播。手机已缓冲的内容仍可能造成实际听到切换的延迟。

## 验证

- 重新请求线上路线目录，确认五个地址来自该路线的中文导游章节。
- 五个地址均返回 HTTP 200、`audio/mpeg`，每个文件均小于 32 MiB。
- 使用本机 FFmpeg 完整解码为 16 kHz 单声道 PCM，五项全部通过。
- 验证记录：`outputs/alipay-idle-audio/ceramics-verification.json`，含来源节点、URL、文件大小、SHA-256 和解码时长。
- 复查脚本：`python -X utf8 outputs/alipay-idle-audio/verify-ceramics.py --ffmpeg C:/ffmpeg/ffmpeg0515/bin/ffmpeg.exe`。

## 部署与复测

1. 将已修改的 WebAPI 配置随正常发布部署，或同步到服务器 WebAPI 发布目录的 `appsettings.json`。确认生产配置或环境变量没有覆盖 `TourAudio:IdleAudio`。
2. 重启 WebAPI。此项仅修改服务端配置，无需更新小程序、数据库或 Nginx；前提是线上已有支持空闲节目的当前后端。
3. 游客退出旧房间后重新加入并开启跟随，确保新建媒体会话读取新的节目列表。
4. 在没有节点讲解和车夫发言的空档确认听到第一段；触发节点后确认节点讲解优先，结束后原节目续播。
