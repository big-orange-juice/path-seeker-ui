# 翻译房间与导航页

H5 与支付宝原生小程序使用相同流程：导航页左下角显示“实时讲解”；创建或加入成功后自动返回导航，入口切换为“房间”。再次点击进入当前房间，继续查看房间码、成员语言与实时译文。入口仅在导航层显示。

创建房间与开启麦克风是两个独立操作。车夫在房间内点击“开始 / 恢复讲解”后，可以返回导航继续操作；游客加入后从下一段完整讲解开始收听。两端内部切页均保留房间连接、字幕信息流及已开启的收音。明确退出房间或切换账号时清理连接、收音和当前信息流。

房主按收听语言查看在线成员昵称及人数，并按讲解段落查看各语言译文。每条译文显示语言、段号、原文与生成状态；同语言游客共享对应译文。游客仅接收自己订阅语言的译文和音频。客户端最多保留最近 60 条译文，刷新 H5 或重新启动小程序不会恢复文字历史。

支付宝实际进入后台时暂停房间连接，回到前台后从房间重新连接。其他讲解音频取得播放权时，房间收听暂停；用户回到房间点击“恢复收听”后接收后续完整音频段，文字流仍可继续更新。

游客房间在底部固定展示译音播放状态与声音控制。H5 加入时在点击手势内播放静音采样以初始化音频输出，并监听浏览器暂停声音的状态；点击“开启 / 恢复声音”直接恢复音频上下文。播放解码失败保留房间与文字连接。译文完成但本段未收到音频时明确提示，不能把“译文已完成”视作“语音已播放”。

房间采用群聊布局：顶部显示房间标题、收听人数与房间码，消息区按讲解顺序从上到下排列。每段原声仅显示一次，房主自己的原声靠右使用浅绿色气泡，各语言译文靠左显示语言头像与“译音助手”名称，避免把自动翻译误认为游客发言。底部固定讲解或收听按钮及音频状态。右上角的更多入口打开房间详情，集中展示邀请码、二维码、成员语言、更换语言、结束及退出操作。查看旧消息时停止自动滚动，可点击“回到最新消息”继续跟随。H5 与支付宝原生页面同步使用该布局。

## 发布依赖

房间界面使用两端共享的八语言词典（简体中文、繁体中文、英语、日语、韩语、法语、德语、西班牙语）。选择收听语言后立即更新房间标题、操作按钮、空状态、聊天状态、播放提示、错误提示和房间详情；重新进入页面、更换订阅和收到房间快照时保留所选语言。房主界面跟随所选讲话语言，服务端订阅确认仅更新游客的界面语言。语言选项使用各语言自称，讲解原文和实际译文保留原始内容；服务端中文错误在显示时映射为所选语言，未知错误使用对应语言的通用提示。本次适配需要同步重新构建并发布 H5 和支付宝前端。

前端与后端需配套发布。后端 `TranslationRoomState` 增加房主可见的在线成员昵称、语言，以及各语言的文字事件；语言音频仍按游客订阅分别下发。成员主键通过字符串传输，不展示手机号或邮箱。

翻译房间使用 `room_translation` 会话类型，任务创建与完成时按当前会话类型更新记录，并保留账号、场馆与运行任务条件。若错误地固定为 `exhibit_qa`，更新记录数为 0，会误报“当前会话已有运行中的任务”，此时翻译模型尚未开始调用。修复该问题无需数据库结构变更，须部署新后端。翻译失败、空译文或输出未完整结束时发送 `language.error`，不再发送成功完成事件；两端显示该段暂不可用，并继续处理后续段落。

语音合成请求成功但没有任何音频数据时，服务端按合成失败处理并下发 `audio.error`，保留译文。房间每段完成日志包含 `Room translation completed` 及 `AudioChunks`：为 0 表示未收到合成音频，大于 0 表示已取得音频并按游客订阅下发，仍需客户端确认播放。不要在日志输出音频内容或接口密钥。

翻译使用后端 `MiniMax:TranslationVoiceId` 作为独立默认音色，未配置或留空时使用 `male-qn-qingse`，与翻译 demo 的初始音色一致。翻译请求显式指定且通过白名单校验的音色仍优先使用；缺省或未知音色不再回退到系统默认导游的克隆音色。普通问答的音色选择保持原有规则。配置源文件为后端 `CulturalTourismSystem.WebApi/appsettings.json`，生产环境可通过 `appsettings.Production.json` 或环境变量 `MiniMax__TranslationVoiceId` 覆盖。修改源码配置后重新发布后端并重启服务；直接修改发布目录中的配置可能在下次发布时丢失。

若房间仍提示合成失败，需要保留警告后的异常正文，例如：`sudo journalctl -u cultural-tourism-api --since "10 minutes ago" --no-pager -o cat | grep -A 25 -B 3 'MiniMax 实时语音合成失败'`。仅筛选含 MiniMax、TTS、audio 的行会漏掉供应商错误原因，不能据此判定欠费。

若异常正文为 PostgreSQL `42601: syntax error at or near "NOT"`，且堆栈指向 `TtsPronunciationResolver.ResolveAsync`，失败发生在合成前的发音词典查询。房间会话没有场馆，原查询中的 `museumId.HasValue` 会被 ORM 翻译成缺少左侧值的 `( IS NOT NULL )`。`TtsPronunciationRepository.GetPublishedAsync` 在构造查询前区分有无场馆：无场馆只读取全局已发布词条，有场馆读取全局及该场馆的已发布词条。修复需要发布后端仓储程序集，无需更改数据库结构或重新发布前端。

H5 生产构建输出在 `apps/h5-client/dist`，支付宝工程输出在 `apps/mp-alipay/dist`。后端项目位于相邻目录 `webapi/CulturalTourism_System`。

## 验证

- H5：`pnpm --filter @path-seeker/h5-client test`，`pnpm --filter @path-seeker/h5-client build`。
- 支付宝：`pnpm --filter @path-seeker/mp-alipay test`，该命令包含原生工程构建。
- 后端：运行 `CulturalTourismSystem.ApiTests` 中的 `TranslationRoomTests`。

真机验收使用一个车夫账号和两个选择不同语言的游客账号：创建/加入后确认返回导航，点击“房间”查看原房间；车夫开始讲解后返回导航，确认游客继续收听；房主确认两种语言的成员和译文分别显示；切换账号后确认旧房间信息清除。自动化测试使用模拟麦克风、音频与套接字，不能代替真机麦克风授权、平台音频行为和翻译服务验收。
