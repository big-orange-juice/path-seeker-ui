# 实时讲解游客反向语音翻译执行计划

日期：2026-11-01。状态：首版代码已实施并完成本地自动化验证，尚未部署或完成真机／真实供应商验收；详见[实施记录](./translation-room-guest-speech.md)。下文保留原计划与排期估算。

## 目标与规模

支持 H5 与支付宝小程序游客在实时讲解房间内发言，识别游客语言，翻译成车夫创建房间时选定的讲话语言，并将译文和译音定向发送给车夫。车夫的回答继续使用现有正向讲解链路。

按下述首版范围估计，这是中等规模功能扩展：约 16～24 个源码、测试及文档文件，约 4～6 个工作日，包含两端开发、后端开发、自动化回归和真机联调。该数字是排期估算，不是完成承诺；支付宝音频行为和供应商实测结果可能影响排期。

## 建议首版行为

- 游客按住“对车夫说话”录音，松开发送，支持取消；单次建议最多 30 秒。
- 默认将游客当前收听语言作为识别语言提示，目标语言由服务器从房间讲话语言读取。首版不自动切换或猜测游客的讲话语言。
- 游客可查看自己的原文、车夫语言译文和处理状态；译音只发给车夫。
- 车夫可查看发言人、原文、译文及待收听状态；其他游客不接收该提问。
- 车夫未开麦且已开启声音时，按服务器接受顺序播放提问译音；浏览器阻止自动播放时显示开启声音入口。
- 车夫正在讲解时，先显示待收听提问，点击“暂停讲解并收听”后关闭采音、处理原有收音尾包，再播放译音。播放后由车夫手动恢复讲解。
- 游客录音期间暂停本机房间译音，录音结束后从后续完整讲解段恢复，不补播录音期间漏听的旧段。
- 房主离线、房间结束或能力未开启时，禁止提交新提问并显示原因。

这是轮流发言流程。若要求车夫开麦时也自动打断讲解并播放提问，或双方持续同时开麦，需扩大音频调度和真机验证范围。

## 现状与复用边界

可复用账号及房间成员校验基础、H5 采音和 WAV 编码、支付宝录音管理及文件上传、MiniMax ASR 客户端、现有翻译和 TTS 服务、音频播放器与部分播放权管理。

必须新增或扩展的部分：

1. 目前后端语音输入只允许房主，不能通过简单取消权限判断实现游客发言。
2. 当前房间广播按目标语言向游客分发；反向提问需要按发言人与车夫定向投递，不能复用普通语言广播。
3. 当前房主不接收语言译音，支付宝房主也未初始化房间音频播放器；两端均需新增房主收听能力。
4. 当前 H5 收听状态及防回声逻辑按房主录音、游客收听设计，需要支持房主暂停采音后播放。
5. 当前 `input.end` 会进入 draining／结束流程，必须新增保留房间的暂停语义。暂停不能关闭房间或取消已经接受的提问。
6. 当前消息键和订阅游标面向车夫讲解段落。游客提问需独立消息标识，避免碰撞或被订阅语言过滤。
7. 支付宝房间收发使用同一连接，房主输入处理期间也要能接收暂停控制；不能用第二个接收循环争抢同一 WebSocket。

## 执行顺序

### 第一步：约定协议、状态和消息展示

- 定义提问状态：已接受、识别中、翻译中、可播放、失败、已过期；本地播放状态单独维护。
- 定义发言人、原语言、目标语言、原文、译文、提问标识及音频归属。
- 提问采用独立事件类型或明确方向字段；车夫讲解和游客提问不共用容易冲突的段号键。
- 房间返回反向提问能力标志；新前端连接不支持该能力的后端时隐藏入口。
- 房间、成员、提问相关业务 ID 在前端和传输契约中统一使用字符串。
- 明确暂停确认、采音尾包处理和恢复握手，旧轮次回调不能影响新轮次。

交付：共享契约、状态转换和接口草案。

### 第二步：后端提问处理与定向下发

- 新增房间内短录音提交入口，建议通过 HTTP 上传 WAV，事件结果复用现有房间 WebSocket；避免支付宝新增并行 Socket。
- 上传前验证成员、房间可提问状态、房主在线、音频格式、时长和大小。
- 将成功接收的录音交给有界处理任务，返回稳定提问标识；同一用户重复提交同一请求不重复识别或播放。
- 复用 ASR，再以房间讲话语言调用翻译与 TTS；提问只翻译一次，不按游客语言数量放大生成。
- 将文字结果发给车夫和发言游客，音频仅发给车夫；其他成员和其他房间均不可收到。
- 增加每人频率、房间待处理数量、处理超时和过期限制；满载时明确拒绝，不无限积压。
- 增加独立的暂停／恢复采音流程；不将暂停映射为正常结束讲解。
- 处理成员退出、账号切换、房主重连、房间关闭和供应商失败；不能在新连接上误播旧连接的音频残片。
- 提问在房主讲话时仍可处理并展示文字，但译音播放等待房主暂停。首版队列设上限与有效期；重连后可标记旧音频不可用，不承诺历史补播。

交付：后端接口、事件、处理队列和针对性测试。

### 第三步：H5 接入

- 游客界面增加按住说话、取消、录音时长、处理中与失败重试。
- 增加游客提问消息展示，保持其与车夫讲解的发言人、方向和状态可区分。
- 房主增加待收听队列及译音播放器，支持“暂停讲解并收听”和手动恢复讲解。
- 调整播放权与防回声：先确认停止采音，再放音；等待期间不提前播放，不误清空待收听提问。
- 退出、切账号、切后台中断、取消录音及权限失败时释放录音资源；过期响应不得更新新房间。
- 新按钮、状态和错误使用现有八语言词典。

交付：H5 完整闭环和自动化回归。

### 第四步：支付宝接入

- 复用录音器所有权、WAV 文件处理和上传能力，扩展为房间提问用途。
- 在原生房间页面增加游客发言、取消、处理状态、消息与车夫收听入口。
- 房主补齐播放器、串行播放和待收听队列。
- 协调录音停止确认、暂停控制和现有事件连接，避免把后续控制帧当作录音数据。
- 验证切后台、录音权限、音频播放失败、临时文件清理和重新进入房间行为。
- 同步八语言文案。

交付：支付宝完整闭环和自动化回归。

### 第五步：交叉联调、发布与回退

- 完成 H5 车夫／H5 游客、H5 车夫／支付宝游客、支付宝车夫／H5 游客、支付宝车夫／支付宝游客四种组合。
- 覆盖英语、日语等游客语言到车夫中文，并验证车夫讲话语言为其他已支持语言的情况。
- 测量松开发送到原文、译文和首个可播放音频的耗时；将实际延迟作为验收记录，不预先承诺固定秒数。
- 验证多人同时提交的顺序、不串音、不重复播放和队列上限。
- 回归现有单向讲解、切语言、返回导航、私人 AI 问答和账号切换。
- 先发布带能力开关的兼容后端，再发布两端；旧客户端忽略新增事件，原讲解流程继续工作。
- 支付宝发布包含开发者工具构建、真机体验及正式版本审核；审核等待不计入开发工时。
- 回退时关闭反向提问入口并取消未完成提问，清理音频资源，保留原单向讲解。

交付：测试结果、真机记录和发布检查结果。

## 估算分配

| 工作项 | 估计工时 |
| --- | --- |
| 协议、状态与消息结构 | 0.5 天 |
| 后端提问链路、定向投递、暂停恢复 | 1～1.5 天 |
| H5 页面和音频流程 | 0.75～1 天 |
| 支付宝页面和音频流程 | 0.75～1.5 天 |
| 回归、交叉真机联调和修正 | 1～1.5 天 |

总量约 4～6 个工作日；各项有重叠，实际以联调暴露的问题为准。预计不需要新增 AI 供应商或单独建设语音基础服务。首版提问采用短期房间内状态，预计无需数据库结构变更；历史持久化、离线重放及报表不在此估算内。

## 首版验收条件

1. 游客录音松开后，车夫能收到身份明确的原文、车夫语言译文和可播放译音。
2. 游客在 H5 或支付宝发言，均能到达 H5 或支付宝车夫端。
3. 正在讲解时收到提问，不关闭房间；暂停后能收听，随后可恢复讲解。
4. 其他游客不收到该提问的文字或音频；房间之间不串消息。
5. 取消、空录音、识别失败、翻译失败和 TTS 失败均有明确状态；有译文无音频时保留译文。
6. 队列、重复提交、弱网、断线、切后台、退出与切账号不会导致重复播报、悬挂麦克风或旧消息污染新房间。
7. 所有既有单向讲解回归通过，并完成真实供应商和两平台真机验证。

## 需要扩大范围时的影响

- 车夫讲解中自动打断、播完自动恢复：增加抢占规则、采音恢复和异常兜底，粗估再增加 1～2 天及对应真机验证。
- 双方持续同时开麦、多人自由插话：需要重新评估输入并发、回声和播放策略，不沿用本计划的工期。
- 提问广播给全体游客并翻译成各自语言：扩展消息权限、各语言队列与生成费用，另行估算。
- 历史提问持久化、离线补收、长录音和语种自动检测：另行设计并估算。
