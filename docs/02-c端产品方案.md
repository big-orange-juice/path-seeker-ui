# Path Seeker C 端产品方案

> 产品名称：Path Seeker / 秘径寻踪  
> 产品形态：移动 H5、微信小程序  
> 文档状态：V1.0 评审稿  
> 适用对象：产品、交互、视觉、前端、后端、内容运营、现场运营、测试

## 1. 产品定义

### 1.1 产品定位

Path Seeker 是面向博物馆现场游客的“主题路线 + 轻解谜 + 智能导览”产品。游客通过扫码或移动端进入，在真实展厅中按路线寻找展品、阅读或收听解说、完成与展品有关的任务，逐步解锁故事、线索、收藏品和成就。

产品不替代真实看展，而是用短任务把游客的注意力从“路过”转化为“观察—理解—记住—分享”。所有任务都应能回到具体展品、展厅和现场动线。

### 1.2 解决的问题

| 用户问题 | 产品回应 |
| --- | --- |
| 不知道看什么、从哪里开始 | 以主题、时长、难度、适龄人群组织路线，提供明确的第一站 |
| 传统讲解信息密度高、容易走神 | 将解说拆成短段落、声音、图片和一次小任务 |
| 只看题目不看展品，互动与知识脱节 | 先观察页再进入谜题，答案必须可由展品或路线线索验证 |
| 同行人进度不一致 | 支持单人和组队，保存个人进度，提供队伍状态 |
| 看完后没有记忆点 | 用线索、碎片、徽章、足迹和结算故事形成闭环 |
| 现场网络、设备和时间不稳定 | 自动保存、断点恢复、重试和降级展示，避免一次失败导致整条路线丢失 |

### 1.3 目标与非目标

**产品目标**

1. 让首次使用者在 60 秒内理解玩法并开始第一站。
2. 让游客在馆内完成一条 15～40 分钟的主题路线，并获得可解释的知识反馈。
3. 让游客在中断后能从最近一个已确认节点继续，不重复消耗已获得的线索。
4. 用展品问答、导游角色和结果分享提升二次探索与自然传播。
5. 建立可量化的“路线开始—节点完成—路线完成—再次游玩”数据链。

**本期非目标**

- 不承诺完整的馆外旅游规划、门票购买或支付能力。
- 不把开放式大模型回答作为唯一判题依据；谜题判定以路线配置和服务端规则为准。
- 不在首版实现复杂社交关系链、公开动态广场或跨馆积分商城。
- 游客账号注销、数据导出等合规能力必须有入口，但不与游戏任务强绑定。

## 2. 用户与场景

### 2.1 用户分层

| 用户 | 特征 | 核心任务 | 设计策略 |
| --- | --- | --- | --- |
| 亲子家庭 | 一名成人带 1～2 名儿童，边走边看 | 共同完成、低门槛、及时鼓励 | 6～10 岁适龄文案，较少文字，清晰的下一步 |
| 学生团体 | 同学或研学小组，时间固定 | 快速进入、分工、完成证明 | 10～15 岁难度，组队入口、进度可见 |
| 年轻游客 | 喜欢主题体验、拍照和分享 | 有氛围、有挑战、结果可传播 | 15+ 难度、视觉叙事、成绩卡和分享文案 |
| 普通散客 | 临时起意，可能只有 15 分钟 | 低承诺试用、随时退出 | 显示时长、站点数、当前拥挤或不可用提示 |
| 无障碍/低视力用户 | 需要更高对比度、语音或较大点击区域 | 理解内容并独立操作 | 字号与对比度可调、朗读和语音导览、触控区域不小于 44px |

### 2.2 典型场景

**扫码即用**：游客在展厅入口或展品旁扫码，选择游客身份或登录，直接进入路线详情；第一次使用不要求先填写完整资料。

**短时游玩**：游客只剩 20 分钟，按“时长/难度”筛选路线，完成 3～5 个站点后可保存进度，后续继续。

**亲子共玩**：家长创建队伍，孩子共同观察展品，团队共享路线完成状态，但每位成员保留自己的徽章与足迹。

**边看边问**：在路线站点或展品详情打开“问一问”，问题自动携带路线和站点上下文，回答附来源和展厅定位。

**网络波动**：提交答案后网络暂时中断，客户端保留草稿和待同步事件，恢复后自动重试；不能重复加分或重复发放奖励。

## 3. 产品架构与信息架构

### 3.1 一级导航

| 一级入口 | 用户心智 | 主要内容 |
| --- | --- | --- |
| 展厅 | “现在有什么可以玩” | 已发布路线、路线筛选、导游入口、馆内入口 |
| 探索 | “我正在进行什么” | 当前进行中的路线、当前站点、队伍状态、继续按钮 |
| 探索记录 | “我玩过什么” | 已完成路线、足迹、成绩、再次游玩 |
| 我的 | “我的收藏与设置” | 个人资料、徽章、收集图鉴、语音偏好、反馈、账号 |

导游详情和“问一问”是二级入口，可从展厅、站点、展品或个人页进入，不打断主路线。

### 3.2 页面与路由基线

| 页面 | 产品职责 | 关键状态 |
| --- | --- | --- |
| 登录/游客进入 | 建立会话、恢复登录态 | 未登录、游客、账号登录、过期、注销 |
| 展厅大厅 | 发现路线 | 加载、空结果、加载失败、局部刷新 |
| 进行中 | 继续当前路线 | 无进行中、单条进行中、多条进行中、队伍同步中 |
| 探索记录 | 查看历史与足迹 | 进行中、已完成、已放弃、分页加载 |
| 我的 | 个人资料和资产 | 未绑定、已登录、资产加载失败 |
| 导游列表/详情 | 了解角色和声音 | 试听中、未配置音色、路线为空 |
| 问一问 | 展品知识问答 | 文本、语音、流式生成、定位、失败重试 |
| 路线地图 | 路线总览与下一步 | 自动加入、节点锁定、当前站、已完成、路线结束 |
| 站点简报 | 观察、解说和进入任务 | 展品资料、地图定位、音频播放、任务入口 |
| 解说导览 | 边走边听 | 播放、暂停、切换速度、音频失效 |
| 章节结果 | 反馈本次站点完成 | 得分、线索、收藏品、下一站 |
| 路线结算 | 完整成果与分享 | 完成、部分完成、重复查看、分享失败 |

## 4. 核心用户流程

### 4.1 主流程

| 阶段 | 用户动作 | 页面输出 | 完成条件 |
| --- | --- | --- | --- |
| 1. 发现 | 浏览、搜索、筛选路线 | 主题、封面、时长、难度、适龄、站点数、导游 | 用户点开路线详情 |
| 2. 评估 | 查看路线故事、展品范围和规则 | 预计时长、集合方式、是否支持组队、奖励说明 | 用户确认开始 |
| 3. 建立会话 | 游客登录或游客进入，选择单人/组队 | 路线会话、队伍码、恢复提示 | 服务端返回有效 session/progress |
| 4. 进入现场 | 查看地图并前往当前站 | 楼层、展厅、点位、路线进度、现场提示 | 用户进入站点 |
| 5. 观察 | 阅读展品卡、听解说、查看可疑细节 | 展品资料、来源、定位、观察清单 | 用户点“开始任务” |
| 6. 解谜 | 完成一个节点交互 | 选择、排序、配对、找线索、推理、密码等 | 服务端判定并记录结果 |
| 7. 反馈 | 查看对错、解析、线索和奖励 | 正确/错误、可用提示、收集品、下一站 | 用户确认继续或退出 |
| 8. 收束 | 完成最后节点 | 真相、成绩卡、知识回收、徽章、分享 | 结算数据落库 |
| 9. 回访 | 再次进入或查看记录 | 足迹、未获得图鉴、排行榜、反馈入口 | 形成二次游玩或分享 |

### 4.2 状态机

    未进入
      -> 已加入/未开始
      -> 进行中
      -> 站点完成
      -> 路线完成
      -> 可重复查看
      -> 已归档

    进行中 --中断--> 可恢复
    进行中 --放弃--> 已放弃（保留历史，不计完成）
    提交中 --网络失败--> 待同步 --成功--> 站点完成

状态变化必须服务端幂等。客户端可以乐观展示“提交中”，但只有服务端确认后才发放分数、徽章和收藏品。

## 5. 功能方案

### 5.1 账号、身份与会话

| 功能 | P0 方案 | 后续增强 |
| --- | --- | --- |
| 游客进入 | 扫码后调用游客登录，创建匿名会话；展示“游客进度仅与本设备/会话关联”的轻提示 | 游客绑定手机号/微信后合并历史进度 |
| 注册登录 | 支持用户名/手机号/邮箱 + 密码；支持刷新令牌 | 第三方登录、免密登录 |
| 过期恢复 | 请求失败先尝试刷新令牌；失败后弹出过期对话框，登录后回到原路径 | 多设备会话管理 |
| 资料 | 昵称、头像、性别、生日、国家/地区、首选语言 | 亲子档案、研学身份 |
| 注销 | 二次确认，说明路线记录、收藏、反馈的影响；调用注销接口后清理本地敏感缓存 | 导出个人数据 |

**验收要求**：用户在站点内登录态过期，不丢失当前草稿、站点上下文和问答输入；登录成功后只能恢复到原路线和原节点，不可越权打开其他用户会话。

### 5.2 路线发现与筛选

路线卡至少显示：封面、标题、主题、导游、预计时长、难度、适龄、站点数、是否支持组队、已完成标记。禁止只展示“好玩”“热门”等无法判断的空泛标签。

筛选条件：关键词、导游、主题/标签、难度、适龄、预计时长、是否支持组队。筛选可组合，清空后恢复默认公开路线；空结果要给出可操作的重置入口。

路线详情包含：

- 故事引子与最终目标，但不提前泄露答案；
- 路线地图或展厅范围；
- 站点数量、必做/选做说明、预计时长；
- 难度、适龄与建议同行方式；
- 导游介绍与试听；
- 奖励类型（线索、碎片、徽章、图鉴）及获得条件；
- “开始路线”“继续路线”“查看结果”三个互斥主动作。

### 5.3 路线会话、单人和组队

**单人**：用户加入路线后生成个人进度；同一路线只能有一个未完成的个人会话，重复点击加入应恢复，不得重复创建。

**组队**：队长创建队伍并分享队伍码；成员输入队伍码加入。队伍共享节点解锁和路线完成状态，分数、徽章和问答历史归属个人。队长可解散，成员可退出；解散前需明确提示所有成员影响。

**继续规则**：进入“探索”默认展示最近活跃路线；进入路线地图时按 currentStageId 或最近已确认节点定位；已完成路线从地图查看，不自动跳转结算页。

### 5.4 现场地图与站点导航

地图展示楼层、展厅、设施、路线节点和当前位置（如有授权）。当前站点突出显示，锁定节点仅显示序号和解锁条件，不泄露谜题答案。

点位信息至少包括：展厅、楼层、点位名称、与展品的绑定关系、建议停留时长、现场安全/不可拍摄提示。找不到精确点位时，降级为展厅级导航，并说明原因。

允许用户手动标记“已到达”仅用于弱行为记录，不能替代必需的谜题或到达判定。地图权限被拒绝时，仍可使用展厅名称和文字路径完成体验。

### 5.5 站点观察与解说

站点必须遵循“先观察、后作答”。观察页展示：展品主图、名称、年代/材质等基础知识、观察清单、相关位置、导游音频、问一问入口和开始任务按钮。

音频能力：播放/暂停、进度、倍速、自动续播、静音状态记忆。音频生成或播放失败时保留文字内容；播放队列只能播当前会话音频，切换站点应停止旧音频。

### 5.6 统一谜题框架

所有题型共用以下结构：题面、作答区、提示入口、提交、判定中、结果解析、重试/继续。服务端按节点 interactionType 判定，客户端不得把本地答案作为最终事实。

| 题型 | 交互 | 适用阶段 | 失败与提示 |
| --- | --- | --- | --- |
| observe_choice 观察选择 | 单选/多选 | 入门 | 错误后展示观察点，不直接展示答案 |
| clue_find 细节找线索 | 点击热点 | 入门 | 命中高亮；误点只给轻反馈 |
| sort 顺序排序 | 拖拽或上下调整 | 中段 | 保存当前顺序，提交后展示正确关系 |
| match 线索配对 | 左右卡片配对 | 中段 | 已配对锁定，错误关系可撤销 |
| image_puzzle 图像拼图 | 碎片换位/拼接 | 中段 | 允许重置，不因刷新丢失草稿 |
| story_branch 剧情判断 | 选择分支 | 转折 | 先展示选择后果，再给事实解析 |
| multi_step_reasoning 多步推理 | 选证据，再下结论 | 高峰前 | 证据链保留，结论未激活前可修改 |
| code_break 密码解锁 | 输入密码/片段 | 终局 | 逐位反馈，达到错误上限后强制提示 |

通用规则：

1. 每次提交生成唯一幂等键，防止重复点击重复计分。
2. 错误不直接结束路线，按内容配置允许重试、扣分或消耗提示。
3. 必做节点未完成时，下一节点保持锁定；选做节点不阻塞主线。
4. 用户主动退出不视为失败，回到地图时恢复草稿。
5. 题面、答案、解析和奖励均来自同一版本的路线配置。

### 5.7 提示、线索与奖励

提示分为观察提示、关系提示、答案结构提示三级，使用前显示可能的扣分或奖励影响。已解锁提示需要持久化，重复进入不得重复扣除。

奖励分为：

- 线索：用于推进剧情或降低下一题难度；
- 碎片/印章/角色卡/文物卡：进入收集图鉴；
- 徽章：按路线、速度、无提示完成等条件点亮；
- 足迹：记录完成的博物馆、展厅和路线。

章节结果页必须回答三件事：“我刚完成了什么”“我获得了什么”“下一步去哪里”。奖励发放以服务端结果为准，客户端只负责动效和展示。

### 5.8 展品问一问

入口：展品观察页、导游详情、底部浮动按钮。打开时可携带路线/站点上下文，但用户界面只显示路线名和站点名，不展示原始 ID。

支持：

- 文本提问；
- 语音提问与回答播放；
- 来源卡片；
- 展厅/楼层/点位定位卡；
- 2～4 条后续问题建议；
- 历史会话和归档；
- 生成中取消、失败重试。

回答边界：只回答服务端配置的博物馆和展品资料；资料不足时明确说“不确定”，不编造年代、出处或位置。位置结果需区分精确点位、多个位置、仅展厅、地图不可用、未绑定。

SSE 事件在产品层的表现：heartbeat 显示生成中，sources 显示来源，exhibit.location 显示定位卡，text.delta 增量展示文本，suggestions 展示追问，done 完成消息，error 提供重试。语音事件失败不应阻塞文字回答。

### 5.9 导游体验

导游列表展示头像、名称、讲解风格、适合人群、关联路线。详情页支持试听和“设为问一问助手音色”；用户偏好只在本地保存，发送时按“用户选择 > 环境默认 > 内置默认”解析。

导游音色未配置、音频过期或试听地址失效时，页面必须保留文本导览并给出可理解的状态，不出现空白播放器。

### 5.10 记录、分享、评价与反馈

探索记录支持按进行中/已完成/已放弃筛选，足迹按完成时间倒序。结算页可生成成绩卡或路线海报，分享内容默认不暴露手机号、精确位置和未公开答案。

完成路线后邀请评价，评价对象、星级、文字和路线上下文绑定；反馈支持匿名提交，用户可查看自己的反馈及处理回复。评价和反馈不应阻塞路线结算。

## 6. 异常、弱网与安全方案

| 场景 | 用户看到的结果 | 系统处理 |
| --- | --- | --- |
| 路线列表失败 | 保留上次缓存并显示“重新加载” | 记录失败原因和重试次数 |
| 进入路线失败 | 返回展厅并保留目标路线 | 不创建半成品会话 |
| 提交超时 | 显示“正在确认”，禁止重复提交 | 使用幂等键轮询或重试 |
| SSE 中断 | 保留已收到的文字，提供继续/重试 | 携带 last event id；超过次数降级普通文本 |
| 音频失败 | 文字继续可读，显示重试 | 不阻塞问答与站点完成 |
| 定位权限拒绝 | 显示展厅级和文字路线 | 不循环弹权限请求 |
| 内容下线 | 当前已开始路线可按策略完成或提示结束 | 新用户不可再加入；服务端返回明确状态 |
| 账号过期 | 弹登录恢复层 | 保留输入草稿和 returnUrl |
| 重复点击 | 按钮进入处理中 | 客户端节流 + 服务端幂等 |
| 未成年人使用 | 不收集非必要敏感信息 | 分享、聊天和公开排名默认隐私保护 |

必须埋点并可追踪：会话 ID、路线 ID、站点 ID、客户端版本、网络类型、事件时间；所有 ID 按字符串传输，禁止在前端转为 Number。

## 7. 数据与指标

### 7.1 北极星指标

**有效完成路线的游客数**：完成至少一条路线且完成过程中成功查看过关联展品内容的去重游客数。它同时约束“完成”与“看展”两个目标，避免只刷题。

### 7.2 漏斗指标

| 指标 | 定义 | V1 建议目标 |
| --- | --- | --- |
| 到达率 | 展厅页面访问人数 / 扫码或入口访问人数 | ≥80% |
| 开始率 | 加入路线人数 / 路线详情访问人数 | ≥35% |
| 首站完成率 | 完成首站人数 / 开始人数 | ≥75% |
| 路线完成率 | 完成路线人数 / 开始人数 | 试点期 ≥15%，优化期 ≥25% |
| 提示使用率 | 使用过提示的场次 / 开始场次 | 监控体验难度，不追求越低越好 |
| 站点流失率 | 离开某站点且未完成人数 / 进入人数 | 重点站点 ≤20% |
| 问答解决率 | 有来源或有效定位的问答 / 问答总数 | ≥85% |
| 次周回访率 | 7 日内再次开始路线的人数 / 完成或中断人数 | ≥15% |
| 分享转化 | 分享卡打开后进入展厅的人数 / 分享卡打开人数 | ≥8% |

### 7.3 事件字典

app_open、route_impression、route_detail_view、route_join、team_create、team_join、stage_enter、stage_observe、narration_play、puzzle_submit、puzzle_result、hint_view、hint_unlock、stage_complete、route_complete、chat_send、chat_source_view、location_open、share_generate、share_open、review_submit、feedback_submit。

所有事件最少带 userId/guestId、sessionId、routeId、stageId、museumId、client、version、occurredAt；涉及大整数的标识统一作为字符串。

## 8. 内容、体验与合规规则

- 文案按 6～10、10～15、15+ 适龄档提供，不只调整字号，还要调整句式、线索显性程度和知识密度。
- 每个谜题必须能回指展品资料或路线故事，内容编辑需提供“答案依据”和“错误解析”。
- 任何 AI 生成的解说、图片、题面、海报都必须标记为待审核，不能自动绕过路线审核直接上架。
- 语音、图片和展品资料需要记录来源、版权状态和更新时间；素材失效时有文字降级。
- C 端不显示内部 ID、接口路径、模型名称、提示词和未公开审核信息。
- 公开排行榜默认使用昵称或匿名化名称，未成年人不默认展示真实头像和联系方式。
- 支持字体放大、系统深色模式、键盘焦点和屏幕阅读器基础语义；动画尊重 prefers-reduced-motion。

## 10. 依赖与验收清单

### 10.1 关键依赖

- 路线、站点、展品、点位、导游和奖励的发布版本接口；
- JoinRoute、Stages、MyRouteProgress、Submit、Hints 等玩法接口；
- 展品问答文本/音频 SSE 及来源、定位事件；
- 账号、队伍、徽章、收集图鉴、排行榜和反馈接口；
- 场馆地图坐标、素材 CDN、音频播放和分享卡生成服务。

### 10.2 V1 验收

1. 新用户从展厅入口到第一站不超过 4 次明确点击，且知道路线时长和难度。
2. 刷新、返回、关闭页面、登录过期和网络重连不会使已确认进度回退。
3. 8 类题型均有题面、草稿、提交中、正确、错误、提示和继续状态。
4. 提交重复、并发提交、重复进入和重复奖励均符合幂等规则。
5. 展品问答能展示回答来源；位置问题能区分点位、展厅和不可用状态。
6. 完成路线后能看到得分、完成数量、耗时、奖励、知识回收和分享入口。
7. 关键埋点能按路线、站点、设备和日期回放漏斗。
