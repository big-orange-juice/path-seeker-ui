# V07、V08、V17、V25、V35、V43、V44 修复记录

本次修改围绕已授权的七项冲突恢复业务流程。保存草稿允许内容未完成；发布沿用实际内容可用性要求；失败操作保留恢复入口；重复操作保留稳定标识和已完成结果。

## 七项修改

| 编号 | 修复后行为 | 兼容处理 |
| --- | --- | --- |
| V07 | 保留前端 12×12 拼图能力；后端校验与自动切图共同采用 144 块上限 | 使用同一个后端常量，前端不缩减到 10×10 |
| V08 | 新文本提示生成 ID，编辑和重复保存保留原 ID | 保留扣分、解锁条件、媒体地址；旧无 ID 提示在两种 JSON 读取链路中得到确定性 ID；媒体提示不会被文本编辑清除 |
| V17 | 无文化点、无展品绑定的开场白、转场和结尾可通过内容发布校验 | 已设置绑定时继续检查实体存在、归属、启用状态等原规则 |
| V25 | 不完整拼图可保存草稿，包括空图片槽及未填写位置的碎片 | 发布再检查原有图片、块数、位置、答案要求；保存保留网格位置；兼容 correct_order 并写入后端标准字段 answer_pieces |
| V35 | Chat 附件数量统一使用已有 ChatMedia:MaxAttachmentsPerMessage 配置 | 移除请求模型、控制器、BFF、引用和粘贴端独立的四张限制；前端读取服务能力；能力暂时不可用时允许提交，由服务层判定；引用图片不再静默截断 |
| V43 | 写入失败的候选条目可重新确认后提交，也可跳过 | 已写入条目不能重复提交；重新确认仍保留对象修改时间，过时覆盖应重新解析；确认和跳过后更新批次计数及状态 |
| V44 | 失败或部分完成批次可以重新解析 | 成功写入条目保留；依据业务编码、已写入目标和同一来源行排除重复候选；候选替换使用事务；失败保留上一轮候选；前端使用最新来源进行映射 |
