# Path Seeker 支付宝原生小程序发布流程

适用于首次发布、后续版本更新和线上故障回退。本文按当前 `apps/mp-alipay` 工程编写，支付宝官方流程核对日期为 **2026-10-15**；控制台按钮名称和可用操作以当前账号、版本状态及平台界面为准。

推荐顺序：**平台配置 → 服务与内容检查 → 构建 → 开发者工具编译与预览 → 上传开发版本 → 体验版真机验收 → 提交审核 → 审核通过 → 灰度或上架 → 线上验收**。

## 2. 首次发布前的平台配置

使用具有相应权限的账号进入 [支付宝开放平台控制台](https://open.alipay.com/develop/manage)，打开 AppID 为 `2021007109685406` 的小程序。

1. 确认小程序归属主体及认证状态，开发账号有该小程序的开发权限，负责提审和上架的账号有对应操作权限。体验成员按控制台规则添加。
2. 完成名称、图标、简介、服务类目及运营联系信息。类目应与实际旅游导览、问答业务一致；按照所选类目提供平台要求的资质，具体材料见 [经营类目与资质](https://opendocs.alipay.com/b/03al2m)。
3. 配置正式隐私政策和数据使用说明，说明定位、录音转写、账号、对话及行程记录的用途。小程序内的说明页不能替代运营方在平台提交的正式隐私政策。
4. 按控制台要求完成定位、麦克风/录音相关能力与权限用途配置；文案应与实际触发操作一致。
5. 配置请求及媒体访问所需域名，保存后核对生效情况。具体操作参照 [打包上传与域名白名单](https://opendocs.alipay.com/mini/ide/upload)。

**开发预览通过不代表域名配置正确。** 官方说明中，上传前的模拟器、手机预览及调试默认不限制域名；上传后的体验版、审核版、灰度版和线上版只允许访问白名单域名。因此必须使用上传后的体验版重新测试网络请求和媒体加载。

域名配置需覆盖：

- API 使用的 `https://www.omahaaigc.com`。配置域名或来源，不要把 `/path-seeker/api` 当成独立域名。
- 后端实际返回的图片、视频、讲解音频和问答音频域名，按平台要求添加到对应配置项。
- 媒体发生重定向时的目标域名。以真实响应和最终资源地址为准，不能只检查接口域名。

所有正式资源应使用有效的 HTTPS 证书。不要把在开发工具里关闭域名校验作为发布验收结果。

## 3. 后端与路线内容准备

当前小程序直接复用寻迹后端，发布包不会自动部署后端，也不会发布路线内容。上传前由接口和内容负责人共同检查：

- API 可从外网访问，证书有效，游客会话、寻迹账号登录/注册、路线目录、站点详情、行程开始/完成/恢复接口可用。
- `ClientCatalog` 中 `rickshaw` 场景至少有一条对应语言的已发布路线。首发至少验收中文路线；对外提供的其他语言也要有可访问的内容。
- 路线包含可用站点、正确经纬度、讲解正文，以及需要播放的图片、音频和视频。未提供某类媒体时应验证页面的空态或降级行为。
- 问答、对话历史、音频回复和语音转写服务可用。要用体验版实际发送录音，确认后端接收到合法 WAV 并返回可用转写文本。
- 如后端有访问频率、账号或地域限制，保证真实用户和审核人员可以完成公开体验流程。

首次打开会自动建立游客会话；账号页面使用现有寻迹账号密码。当前没有支付宝账号授权登录，也没有支付、订单功能，发布简介和审核说明应与这个范围一致。

可用于指定路线的页面路径如下，业务 ID 全程使用字符串：

```text
pages/tour/index?routeId=实际字符串路线ID&destinationId=实际字符串目的地ID&lang=zh
```

填写入口路径时，将示例值替换成真实已发布内容；不要将长 ID 转成数字或使用会丢失精度的表格数值单元格。

## 4. 生成发布候选包

在仓库根目录执行，命令失败时先修复，再进入上传流程：

```powershell
pnpm install
pnpm build:mp-alipay
pnpm test:mp-alipay
git diff --check
```

已有依赖且未变更依赖声明时，可以跳过安装。`test:mp-alipay` 会重新构建再运行测试。发布时记录实际测试数量和结果，不要直接复制此前的通过记录。

构建前核对以下文件：

| 文件 | 核对内容 |
| --- | --- |
| `src/config.js` | `appId`、`apiBase`、默认音色和支持语言 |
| `mini.project.json` | `appid` 为 `2021007109685406`，代码根目录为 `dist` |
| `src/app.json` | 页面、原生标签栏和权限相关声明符合本次发布需求 |

工程路径均相对于 `apps/mp-alipay`。修改源码后重新构建；不要直接修改 `dist`，下次构建会覆盖它。

上传前记录候选代码的 Git 提交号，以及尚未提交的变更。正式发布应能够对应到可复现的源码版本。可用以下命令查看，避免上传其他开发中但未验收的功能：

```powershell
git rev-parse HEAD
git status --short
```

停止开发监听或持续改动后再制作最终候选包，确保体验版验收、提审和上架对应同一份代码。开放平台上传版本号可使用 `1.0.0`、`1.0.1` 等约定；工程 `package.json` 的版本号不会自动同步到平台，上传时单独核对并记录。

## 5. 开发者工具编译与手机预览

1. 安装 [支付宝小程序开发者工具](https://opendocs.alipay.com/mini/ide/download)，登录具有该 AppID 开发权限的支付宝账号。
2. 导入 `apps/mp-alipay`，选择支付宝小程序。工程配置会把实际代码目录指向 `dist`。
3. 若工具版本要求直接导入代码目录，可导入 `apps/mp-alipay/dist`；构建会生成其中的独立 `mini.project.json`，其代码根目录为 `.`。
4. 确认关联的是 `2021007109685406`，执行工具原生编译，排除 AXML、ACSS、组件、原生 API 及运行时错误。
5. 检查“漫游”“问一问”“我的”入口和页面跳转，查看控制台中的请求失败与资源错误。
6. 使用真机预览检查基础交互、地图、定位、音频和录音。记录手机系统、机型、支付宝版本及开发工具版本。

模拟器通过后仍需真机测试，尤其是原生定位、音频生命周期及录音上传。这里的预览用于排除基础问题；域名和发布环境验收继续在下一步体验版完成。

## 6. 上传并生成体验版

1. 在开发者工具工具栏选择 **上传**，按提示填写候选版本号与版本描述，再次核对 AppID。
2. 上传成功后，打开控制台中该小程序的 **版本管理**，确认新生成的 **开发版本**、版本号、上传时间及描述。
3. 将本次候选开发版本 **设为体验版**，按控制台要求添加体验成员或配置体验权限。
4. 使用控制台生成的体验入口或二维码，由体验成员在手机上打开。确认进入的是本次体验版本。
5. 完成下表验收。出现阻断问题时修复源码、重新构建和上传，将新候选版本设为体验版后复验；被修复影响的相关流程也要重测。

验收时应了解当前产品行为：

- 问答采用完整响应后展示，当前没有逐字流式输出；问答及转写等待上限为 120 秒。停止等待后，服务端仍可能已生成并保存对话。

## 8. 提交审核

在 **版本管理 → 本次开发版本 → 提交审核** 中完成自检，填写版本信息和小程序信息，再提交。以实际控制台要求为准，准备：

- 与当前功能一致的名称、简介、类目、图标、截图、服务说明和版本变更说明。
- 所选类目所需资质、正式隐私政策、权限用途和运营联系人。
- 清晰的体验步骤及可访问的路线内容。首次公开页面应让审核人员能够理解业务并进入体验。
- 如果需要验证必须登录的功能，按平台表单要求提供有效测试账号。密码通过审核表单或受控渠道提供，不写入代码仓库、本文或公开截图。
- GPS 触发需要到达实际站点，可在审核说明中解释条件，同时提供手动浏览和正式进入站点的路径，便于审核基础导览功能。

可按真实业务名称调整以下服务说明：

> 提供目的地路线与景点导览，支持地图查看、图文及音视频讲解、手动进入站点和定位辅助播放。用户可通过文字或录音转写提出问题，查看回答、资料来源及对话记录，并查看个人行程与足迹。首次打开支持游客体验，可选用寻迹账号登录。

建议填写的审核体验路径：

1. 打开小程序，等待游客会话及路线目录加载。
2. 在“漫游”选择已有内容的目的地、路线和中文讲解，打开站点查看图文及媒体。
3. 正式进入站点，播放讲解或使用手动完成，查看行程状态。
4. 进入“问一问”，发送一个与当前景点相关的问题，查看答案和资料来源。
5. 点击录音，按需授权麦克风，录制至少 1 秒后结束；转写出现在输入框，点击发送。
6. 进入“我的”，检查记录、语言/音色及权限说明；如需登录验证，按提交的测试账号操作。

审核期间保持后端、媒体和路线内容可用。官方快速接入指南写明审核通常在 **2 个工作日内**完成，实际耗时以平台为准，不作为确定上线时间承诺。

如需取消当前审核，可在审核中的版本选择 **撤回审核**。审核失败时读取具体驳回原因，对照 [常见审核驳回](https://opendocs.alipay.com/b/03al5a) 修复；需要改代码时重新构建、上传并验收，按控制台流程退回开发或重新提交审核。

## 9. 审核通过后上架与线上验收

1. 确认审核通过的是已经完成体验验收的候选版本，核对版本号、源码版本和变更说明。
2. 如控制台提供 **灰度测试**，可先向部分用户开放，观察启动、路线加载、问答、录音及后端异常；满足本次验收要求后再 **上架**。灰度属于可选步骤，是否可用以控制台为准。
3. 按版本当前状态执行上架操作，确认控制台显示本次版本为 **线上版本**，记录版本号、操作人和时间。
4. 从正式搜索、正式分享入口或正式二维码进入，确认访问的是线上版本。开发预览和体验二维码不能代替线上验收。
5. 至少复验游客进入、路线加载、一次正式行程、讲解播放、文字问答和录音转写；核对图片、视频及音频域名限制。
6. 检查平台与后端可用的错误信息和请求日志，关注认证失败、资源访问失败、转写失败及接口超时。排查材料中不要暴露访问令牌、用户密码或个人录音。

发现影响核心流程的故障时按下一节处理，并在发布记录中填写症状、影响范围和处理结果。

## 10. 后续更新、回滚与下架

### 常规更新

每次更新都重新生成候选包、执行本地检查、上传新开发版本、验收体验版、提交审核并上架。不要假定上一版本的域名验证、录音结果和内容可用性仍适用于新版本。发布说明写清用户可见变化，接口变更要兼容仍在使用旧版本的用户。

### 回滚到上一版本

官方流程提供 **小程序详情 → 版本管理 → 线上版本右侧的回滚 → 返回上一版本**。操作前确认控制台实际提供此入口，且上一版本可用并与当前后端兼容。首次发布通常没有可回退的线上版本，不能预设一定可回滚。

回滚前记录当前版本、目标版本、故障及决策人；回滚后从正式入口验证版本和核心功能。小程序代码回滚不会自动撤销后端部署、数据变更、域名或隐私配置，相关问题需要由对应负责人单独处理。

### 下架

**下架与回滚不同。** 下架会停止该版本的线上服务。官方说明下架版本不能恢复；再次上线需要上传并重新审核新版本。因此不要把下架当成可以随时恢复的暂停开关，操作前应明确业务影响和恢复路径。

本文仅记录操作流程，实际回滚、下架及上架由具备相应权限的发布负责人执行。

## 11. 常见发布问题

| 现象 | 优先检查 |
| --- | --- |
| 预览正常，体验版/线上版请求失败 | 对应 AppID 的域名白名单、生效状态、HTTPS 证书及重定向目标；检查实际错误信息 |
| 打开后没有路线 | API 是否可达、游客会话是否成功、`rickshaw` 场景及当前语言是否有已发布路线 |
| 图片可见但音频或视频失败 | 实际媒体域名、最终 URL、资源可访问性和格式；主讲解失败时确认正文/手动完成可用 |
| 模拟器正常，真机无法录音或转写 | 支付宝版本、麦克风权限、录音时长、WAV 数据与 multipart 格式、接口响应 |
| 问答长时间没有文字出现 | 当前为完整响应后展示；检查后端处理耗时、120 秒超时及体验版网络请求 |
| 定位没有触发讲解 | 是否授权、页面是否在前台、真实位置与站点范围、坐标数据、固定内容/自动播放开关 |
| 登录后记录不一致 | 当前账号、会话状态、本机户外记录与服务端探索记录的区别，不要假定全量跨设备同步 |
| 上架后仍看到旧内容 | 核对实际打开的版本和入口、平台版本状态、后端内容发布及本机选择的路线/语言 |
| 审核人员无法体验 | 路线是否公开可用、测试账号是否有效、业务类目/权限说明是否准确、是否提供手动体验路径 |
