# 车夫位置与到站判定验收

2026-11-03 起，小程序导览只读取当前房间的车夫位置，不再调用支付宝定位。旧版 `my.getLocation` 的轮询、缓存、权限和后台定位验证不再适用。路线纠偏仍由 `routeCorrection: false` 关闭。

## 前置条件

- 后台已部署 `GET /TranslationRooms/{roomId}/location`，该接口校验有效游客、房间成员和车夫权限。
- Android APP 使用 0.3.0，创建同一讲解房间并开启位置共享；B 端可核对该房间上报。
- 游客使用不同账号加入房间，进入正式路线行程并开启「跟随车夫」。

## 数据与触发

1. 游客手机保持静止，仅移动车夫手机。地图的车夫标记、回中和近站判定都应使用 APP 上报位置。
2. 未加入房间时，开启跟随只能显示加入提示；关闭游客手机系统定位、拒绝支付宝定位权限也不影响车夫坐标读取，不应弹定位授权。
3. 请求完成后约 1 秒再次查询。APP 约 3 秒上报新样本，重复 sampledAt 不能刷新样本年龄、累计新的定位帧或重新开始提示倒计时。
4. 地图使用 GCJ-02；近站范围沿用现有 WGS84 计算。不要在本轮更改已配置路线和范围坐标。
5. 精度超过 65 米、未知坐标、15 秒前的样本、未来超过 2 秒的样本和倒序采样不能参与到站判定。页面显示真实精度，不通过扩大景点范围弥补定位误差。
6. 在圆形和多边形范围附近保持至少两次不同采样，跨度至少 1.5 秒；出现 3 秒提示卡后，再次核验仍接近时进入队列。
7. 实时讲解收听期间依然可根据车夫位置排队，景点音频等待实时讲解解除占用后再播放，不能抢音。

## 中断与隔离

1. 停止 APP 位置共享、断网、返回旧样本或关闭房间，确认待确认卡、停留状态和车夫标记清除，不继续自动触发。
2. 连续网络请求失败或同一采样未更新超过 15 秒，确认客户端过期定时器会清理旧位置，即使没有新响应也不能继续触发。
3. 关闭跟随、离房、换房或切账号，确认取消旧请求；迟到响应不能恢复旧车夫标记、卡片或触发站点。
4. 恢复前台后取消旧查询，重新获取当前位置并重新稳定判断，不补造经过站点，也不使用恢复前的旧停留时间。
5. 使用未加入该房间的账号访问位置接口必须失败；接口不能返回手机号、车夫账号 ID、其他房间位置或历史轨迹。

## 息屏边界

车夫 APP 的定位和麦克风前台服务分别做真机锁屏 10～30 分钟验证。游客支付宝小程序的查询、计时器、WebSocket 和自动播放受支付宝后台调度限制，服务器持续收到车夫坐标不等于游客息屏仍能实时播放。

分别记录 Android 和 iPhone 的支付宝版本、系统版本、网络、息屏时刻、坐标更新时间、恢复前台后的行为。单元测试和模拟器不能证明息屏能力。协议与部署说明见 `docs/driver-commentary-integration.md`。
